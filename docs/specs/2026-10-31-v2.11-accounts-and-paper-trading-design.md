## 1. 目标

对应路线新增成功标准 9（§19）：**系统里有账本而不只是快照：真实账户与模拟账户同一套口径——初始现金、每笔成交、每日权益、持仓与回撤；Agent 在一个不花真钱的账户里每天看着自己的持仓和现金决定买什么、买多少、何时卖，判定仍在宿主；另有一个机械照计划执行的账户作对照，三个账户的曲线与指标能并排看，说得出「计划好不好」和「挑选与仓位好不好」各是哪一层的差异。**

用户的两条目标与对应交付：

| 用户原话 | 现状（核查） | 交付 |
| --- | --- | --- |
| 账户模块，包括真实账户 / 模拟账户，模拟账户可由 Agent 自动管理 | 系统里只有一个隐含的真实账户：`trades`（成交）、`account_snapshots`（手动录的月末券商权益）、`cash_flows`（出入金）都没有账户维度；权益是「你录的数」不是「算出来的」；`plan-shadow-2` 逐份计划纸上回放、以 R 计、没有现金与仓位约束，不成账户 | §4 账户与账本 `account-1`；§5 模拟账户：Agent 自管 `agent-portfolio-1` 与照计划执行 `follow-plans-1`，统一成交规则 `paper-fill-1`；§6 `daily` 图新节点 `accounts` |
| 交易记录录入，关联账户金额情况 | 成交录入在「复盘 → 交易与持仓」，不挑账户；没有现金余额、持仓市值、每日权益 | §4.3 每日权益日志；§8 接口；§9 新顶级菜单「账户」（成交录入与出入金搬过来并带账户选择） |

**最终目的**（用户 2026-10-31）：优化真实账户的策略。所以模拟账户只能买 **Agent 出过计划的标的**，不另选股；三个账户的候选来源完全一致，差异才可归因。

**不改的口径**：规则 v1、`screen-1`、`regime-2`、`timeline-2`、`entry-1`、`plan-shadow-2`、`execution-1`、`agent-3`、`agent-review-2`、`discipline-2`、`tracks-2`、`retro-2`、`review-8`、知识三件。链状态（`timeline-2`）**只由真实账户的成交推出**，模拟账户的成交不改变任何链的状态（D4）。所有规则与 Agent 照旧**未经验证**（Phase 0 Gate HOLD）。

## 2. 假设与决定

用户在讨论里已定的（见 §18 对照）不再重复。下表是本 spec 补定的设计决定；会改变真实数据语义或范围、需要你拍板的列在 §17「待用户确认」，并按建议方案先写进本文。

| # | 问题 | 决定 | 理由 | 放弃的备选 |
| --- | --- | --- | --- | --- |
| D1 | 账户怎么建模 | 新表 **`accounts`**（§7.1）：`kind` 真实 / 模拟，`strategy` 手动 / Agent 自管 / 照计划执行，初始现金与开户日，仓位参数（每笔风险、单票上限、总仓位上限）存在账户上；`trades`、`account_snapshots`、`cash_flows`、`holding_status` 加 `account_id` | 三个账户同一套成交 / 持仓 / 权益口径，纯函数加账户参数即可复用；仓位参数从全局配置下沉到账户，每个账户各自一套（`config.workbench` 的三个值只作新建账户时的默认值） | 模拟账户另建 `paper_*` 表（复盘机器全部要再写一遍） |
| D2 | 旧行归谁 | 迁移 030 建默认真实账户一行（固定 id `00000000-0000-0000-0000-000000000001`，`name = 真实账户`，`kind = real`，`strategy = manual`，初始现金与开户日为空），四张表的 `account_id` 列 `NOT NULL DEFAULT <该 id>`；旧行由默认值归入 | 真实库没有成交与持仓，只有可能有的月末快照与出入金；默认值不改旧行语义。这是本项目第一次在迁移里写种子行，只写这一行，且 `INSERT … ON CONFLICT DO NOTHING` 可重跑 | 旧行 `account_id` 留空（所有读取都要兼容空值） |
| D3 | 真实账户的权益 | **账本模型 `account-1`**（§4）：权益 = 现金 + 持仓 × 最近收盘；现金 = 初始现金 + 出入金 − 买入成本 + 卖出所得。你要录一次**初始现金与开户日**（§8.1）才有权益；录之前真实账户的权益为「未开账」（`no_opening`），建议股数仍按旧办法用快照（D6）。券商月末快照保留为**对账**（§4.4） | 用户要「跟进账户金额变化」，快照一个月一个点做不到；模拟账户只能用账本，真实账户不同口径就不可比 | 真实账户继续用快照、只有模拟账户用账本（曲线不可比） |
| D4 | 链状态与模拟成交 | `timeline-2`、`execution-1`、`discipline-2`、`tracks-2`、`retro-2`、复盘卡、周 / 月快照、持仓状态的「持仓」**一律只看真实账户的成交**：`repository.list_trades` 等读成交的函数加 `account_id` 参数，缺省 = 默认真实账户。模拟账户的纪律 / 轨道由页面显式传账户现算（§8.4） | 链是「你照着做的那一版」的证据链，模拟成交不是你做的；缺省真实账户让全部既有调用方行为不变 | 模拟成交也推链状态（Agent 自管账户一买，链就「持仓」，真实账户的计划表会乱） |
| D5 | 模拟账户的候选范围 | Agent 自管账户与照计划执行账户都只能买 **`agent-3` 链在当天收盘时处于入场期的链头版本**所属的标的（`timeline-2` 状态 `entry`），每条链在一个账户里至多一个在挂的买单；不买规则基线、不买自定计划、不买无链单元 | 用户：「他提供交易计划的标的」；链头 = 当时能照着做的那一版，与真实账户成交关联的规则（R6）一致 | 允许买规则基线（对照失焦：就变成「规则 vs Agent」而不是「Agent 挑选 vs 机械」） |
| D6 | 建议股数用哪个权益 | `plan` 节点与 `agent-3` 的建议股数（`plans.size`）改读**真实账户当天的账本权益**（`account_equity_days` 的最新一行，§4.3）；真实账户未开账时回退到快照头（现状），`sizing.equity_source` 记 `ledger` / `snapshot`。模拟账户的股数在下单时按**本账户**的权益与参数另算 | 建议股数本来就该跟着实际权益走；回退让开账前行为不变 | 改口径发 `plan-3`（公式没变，只是输入来源；`sizing` 里记来源即可分辨） |
| D7 | 模拟账户的成交怎么成 | 统一规则 **`paper-fill-1`**（§5.3）：买单按 `entry-1` 的开盘三种情形用**次一交易日**的真实日线成交或作废（复用 `entry_rules.simulate_entry`）；退出按计划规则由宿主自动执行：止损（当天最低 ≤ 止损 → 跳空穿过按开盘价、否则按止损价）、到 T1 卖一半（按 T1 价）、T1 后 3 ATR 移动止损、时间止损（次日开盘）；Agent 自管账户的主动卖出按次一交易日开盘价。手续费与滑点取账户参数，默认 0 | 与 `plan-shadow-2` 同一套假设，影子与账户不打架；判定在宿主 | 盘中价位（没有盘中行情源，roadmap §6.3 暂缓） |
| D8 | Agent 自管账户里 Agent 的自由度 | 买入必须指向当天允许的 `plan_id`（D5），**止损 / T1 / 入场区间 / 入场类型用那一版的**，不得另定；可决定的：买哪几份、买多少股（≤ 宿主算出的上限）、撤掉自己还没成交的挂单、提前卖出持仓（全部或一半，次日开盘）；**不能**取消宿主的止损 / 时间止损 / T1 卖半。价位不对的出口是在链上出修订版（`user_inputs` → 重新复查），不在账户里改 | 用户讨论定：模拟成交与真实成交一样挂 `plan_id`，整套机器复用；「计划」与「挑选 / 仓位 / 卖点」分层归因；止损只能上移（白板 6.2） | 允许 Agent 死扛止损（等于把纪律第三项让给模型） |
| D9 | 订单的合法性检查 | 宿主逐条检查，**不合规的订单拒绝并记录原因，不替它改数**（§5.2.3）：`plan_id` 不在允许集、股数 > 上限、现金不足（股数 × 入场上沿 + 费用 > 现金 − 其他在挂买单占用）、同一链已有在挂买单、卖出股数 > 持仓、理由缺失或超长。拒绝的订单与理由存下来，次日作为证据给 Agent 看 | 用户讨论定；替它减到上限会让「它想买多少」这个信号消失 | 自动缩到上限 |
| D10 | 照计划执行账户的规则 | **`follow-plans-1`**（§5.4）：当天每条入场期链头版本，若本账户没有该链的持仓与在挂买单，就按本账户参数算股数挂买单（`no_room` 记跳过）；链出修订版时换成新版的价位（旧单撤、新单挂，同一链一个单）；链结束（过期 / 作废 / 被取代）时撤单；退出全按 D7；不主动卖 | 它是「Agent 的计划全部照做」的对照：挑选为空、仓位为标准 | 按影子 `plan-shadow-2` 的每份计划结果拼账户（没有现金与仓位约束，不可比） |
| D11 | Agent 自管的模型调用 | 单阶段图 `run_portfolio`（提示词 **`agent-portfolio-1`**，§5.2），每个 Agent 自管账户每个交易日**一次**调用；证据块给全部数字（账户、持仓、在挂单、可买计划、环境、近 20 个交易日本账户的结束交易、昨日被拒绝的订单），工具只允许 `get_price_bars`、`get_indicators`、`get_market_context`、`get_concept`、`get_knowledge`，标的限持仓 ∪ 可买计划；输出 JSON（订单、持有理由、一句总结），宿主做结构校验与 D9 检查。**不做引用校验**：它不写价位，股数由宿主重算 | 与每日复查同构，复用 `_build_single_graph`、工具记录、推理视图；一天一次与 `daily` 的节奏一致 | 多阶段（提议 + 反方）：每天一次组合决策不值一次反方调用；留 backlog |
| D12 | 模型不可用那天 | Agent 自管账户「不动」：在挂买单照旧按 `paper-fill-1` 等成交，宿主退出照旧执行，不新开单；决策记录写一行 `status = skipped` 与原因；额度用尽、未连接、输出不合法同此。照计划执行账户不依赖模型，照常 | 与 v2.8 的「Agent 不可用整节点跳过、其余照常」一致 | 用昨天的决定重放（没有依据） |
| D13 | 新节点在哪 | `daily` 图加一个节点 **`accounts`**，排在 `review` 之后、`push` 之前（§6）。节点内顺序：①结算（所有模拟账户：昨天的挂单用今天刚收盘的日线成交 / 作废，持仓按 D7 退出）→ ②三个账户各写一行当日权益 → ③模拟账户的持仓状态行 → ④决策（照计划执行账户机械挂单；Agent 自管账户调模型、校验、挂单）。阶段版本升 **`stages-5`**（11 个节点）、图版本 **`daily-2`** | 用户选方案 A；`review` 节点写真实账户的持仓状态（不变），模拟账户的持仓状态由本节点在结算之后写，顺序才对；节点级续跑、详情页、失败通知全部复用 | 独立定时任务（用户放弃）；塞进 `review` 节点（节点职责混、失败互相牵连） |
| D14 | 幂等与续跑 | 结算以 `(order_id, session)` 唯一；权益日志以 `(account_id, session, computed_at)` 追加、读取取最新；决策记录以 `(account_id, session)` 唯一，同 session 重跑 `ON CONFLICT DO NOTHING` 并读回已有行（模型不会被调第二次）；手动运行 `daily` 与定时运行同样写（与 v2.9 持仓状态相同） | 一天一次是账户口径的一部分：同一天两次决策会把挂单翻倍 | 手动运行不写模拟账户（手动验收时看不到效果） |
| D15 | 真实账户当日权益的时效 | 真实账户的权益行在 `accounts` 节点按**运行时刻已录入**的成交与出入金算；你事后补录成交时，下一次运行**重算最近 5 个交易日**，数字变了就追加新行（`computed_at` 更新、`supersedes` 语义同快照），页面与月度口径取最新行。模拟账户的成交由宿主写，不会事后变 | 只追加；补录是常态（成交当天晚上录，运行在中午） | 补录时同步重算（录入接口要做权益计算，耦合） |
| D16 | 月度收益率 | **`monthly-5`**：真实账户的月度收益率改为 (月末账本权益 − 上月末账本权益 − 区间净出入金) ÷ 上月末账本权益，两端都取 `account_equity_days` 该月最后一个交易日的最新行；真实账户未开账、或任一端缺行时回退到快照口径（`monthly-4` 的公式，`source = snapshot`）。主指标仍只认真实账户；旧 `monthly-4` 快照不重算 | 用户讨论定「月度收益率改从权益日志算，快照退为对账」；回退保证开账前每月仍出数 | 两套并列（主指标只能有一个） |
| D17 | 对账 | 真实账户每条券商快照与同日（`as_of` 所在交易日）账本权益比：差额与百分比超过 **1% 或 100 美元**（账户参数 `reconcile_tolerance_pct` / `_abs`）标「待核对」，显示在「账户 → 真实账户 → 概览」的对账块与「资金」表格；只提示，不自动修正任何记录 | 快照是外部事实，账本是内部推导，两者不一致说明漏录或费率假设错 | 用快照覆盖账本权益（破坏账本） |
| D18 | 复盘怎么并表 | 纪律 `discipline-2`、轨道对比 `tracks-2` 加 `account_id` 参数（缺省真实账户），复盘页这两个页签顶部加账户切换、现算不落库；周 / 月复盘快照、复盘卡、对照组、「我的知识」**只对真实账户**；模拟账户的收益率、回撤、胜率、平均 R、纪律计数集中在「账户 → 对比」（§9.3），结束的交易只出事实行 | 用户讨论定：复盘卡花额度且经你审定进知识，模拟账户不进；对照组与账户无关 | 模拟账户也出复盘卡（每天可能多张，起草上限 5 张会积压） |
| D19 | 默认的两个模拟账户 | 迁移**不**建模拟账户；上线后你在「账户」页新建两个（默认名「Agent 自管」「照计划执行」，初始现金默认 100 000 美元、参数默认取 `config.workbench`），也可以再开更多（如换一组风险参数的 Agent 自管账户）；账户只能**关闭**（`status = closed`，不再决策与结算、历史全留），不能删 | 初始金额是你定的，不进迁移；多开账户正是「策略进化」的容器 | 迁移里种两个账户（金额写死） |
| D20 | 推送 | 本版**不改**每日推送内容（无新段）；`accounts` 节点失败与 Agent 自管账户的 `skipped` 只进运行报告与详情页，不单独通知 | 推送是给你明早行动用的，模拟账户的动作不需要你做什么；少一处格式变更 | 推送加「模拟账户今日」一段（留 backlog，看一周后要不要） |

**做**：§4 账户与账本（`accounts` 表、四张表加账户列、每日权益日志、对账、开账）；§5 模拟账户（Agent 自管、照计划执行、`paper-fill-1`、订单与决策记录）；§6 `daily` 新节点；§7 迁移 030；§8 接口与 CLI；§9 前端（新菜单「账户」五个页签、复盘页搬迁与账户切换、成交录入带账户）；§10 概念卡与原理页；§11–§16 出错、测试、风险、限制、文档。

**不做**（用户已定的，加本 spec 的取舍）：

- 券商接入、自动下单、同步券商流水（永久不做）；盘中 / 盘前价格；模拟账户买规则基线、自定计划或任何没有 Agent 计划的标的；Agent 自选股（v2.13 主动研究的事）。

- 多账户的真实账户（只一个真实账户；多券商合并成一个账本）；账户间转账；币种（只美元）。
- 做空、期权、分批入场 / 分批止盈、追高比例（backlog 不变）；Agent 自管账户的加仓（同一链一个买单、持有期间不再买）。
- 回撤阶梯（白板 5.4：−5% 减半仓、−7.5% 停手）作为宿主规则——只在对比页**显示**回撤，不自动降风险；等有三个月数据再议。
- 手动触发「重新决策」按钮（同 `rerun_agent`）；Agent 自管账户之间的对抗。
- 删除或改写任何旧行（`account_snapshots`、`cash_flows`、`trades` 只加列）。

## 4. 账户与账本（`account-1`）

### 4.1 账户

| 字段 | 真实账户 | 模拟账户 |
| --- | --- | --- |
| `kind` | `real`，全库恰好一个（部分唯一索引） | `paper`，可多个 |
| `strategy` | `manual`（你下单你录入） | `agent_managed` 或 `follow_plans` |
| `opening_cash`、`opened_on` | 开账时你录入一次（§8.1），录入后不可改（改错就关闭账户另开，真实账户不能关闭，所以开账前页面要你确认两次） | 新建时必填，> 0 |
| `params` | `risk_pct`、`single_cap`、`total_cap`（默认 `config.workbench`）、`fee_per_trade`（默认 0）、`reconcile_tolerance_pct`（默认 0.01）、`reconcile_tolerance_abs`（默认 100） | 同左，另加 `max_positions`（默认 8，Agent 自管与照计划执行都受限）；`reconcile_*` 不用 |
| `status` | 恒 `active` | `active` / `closed`，关闭写 `closed_at` 与原因 |

参数存 JSONB，建账后**可以改**（写一行 `account_param_changes`，§7.1；改动从下一个交易日的决策起生效，不重算历史），这是模拟账户之间唯一允许的「调参」，也是它们存在的意义。

### 4.2 现金、持仓与权益

全部纯函数（`accounts.py`），输入是截止时间之前的记录：

| 量 | 公式 |
| --- | --- |
| 现金（`cash`） | `opening_cash` + Σ未作废出入金（只真实账户有）− Σ买入(股数 × 价 + 费) + Σ卖出(股数 × 价 − 费)，按 `executed_at ≤ 截止` 的未作废成交 |
| 持仓（`positions`） | `positions.build` 按账户的成交先进先出（现有函数，只是输入换成该账户的成交）；每只给数量、成本、最近收盘、市值、浮盈、R（按该持仓的有效止损，口径同持仓状态） |
| 持仓市值 | Σ数量 × 该标的 ≤ 截止日的最近收盘（拆股用 `split_events` 换算到当前基准） |
| 权益（`equity`） | 现金 + 持仓市值 |
| 已实现盈亏（累计） | Σ`positions.build` 的 `closed[].realized_pnl` |
| 当日盈亏 | 今日权益 − 昨日权益 − 今日净出入金 |
| 自开户收益率 | (权益 − 初始现金 − 累计净出入金) ÷ 初始现金（有出入金时按 Dietz 简化：分母加 Σ出入金 × 剩余天数占比；真实账户出入金少，页面注明口径） |
| 最大回撤 | 权益序列（按交易日）的最大峰谷跌幅与起止日 |

### 4.3 每日权益日志 `account_equity_days`

`accounts` 节点每个交易日给每个活跃账户写一行（§7.4）：`cash`、`positions_value`、`equity`、`realized_pnl_cum`、`unrealized_pnl`、`net_flows_cum`、`day_pnl`、`positions_count`、`detail`（每只持仓的数量、收盘、市值；缺收盘的标的列在 `bars_missing`，市值按最近有的收盘算并标 `stale`）。真实账户按 D15 重算最近 5 个交易日。

未开账的真实账户不写行（页面写「未开账：录入初始现金与开户日后开始记账」）。

### 4.4 对账（真实账户）

每条未被取代的券商快照 → 找 `as_of` 所在（或之前最近）交易日的最新权益行 → `diff = snapshot.equity − ledger.equity`，`pct = diff ÷ ledger.equity`；超出容差标 `status = mismatch`，否则 `matched`；没有权益行标 `no_ledger`。只读视图，不落库。

## 5. 模拟账户

### 5.1 可买集合（每个交易日 S 收盘时算，两种模拟账户共用）

`buyable(S)` = 所有 `agent-3` 链中，S 收盘时链未结束（`timeline-2` 的 `invalidated` / `expired` / `superseded` 以外；`holding` / `exiting` / `position_closed` 只是真实账户的事，不排除）且其**最新一版入场期版本**（`inputs.chain_mode ≠ 'holding'`）的有效期覆盖 S+1 的那一版（D23），`next_open` 类型只在 `valid_from = S+1` 时列入（D24）。每项带：`plan_id`、标的、链 `signal_date`、`version_no`、入场类型与区间、止损、T1、`valid_from` / `valid_until`、`max_hold_sessions`、链的最近一次复查结论、相对上一版的变化文本、链在真实账户里的状态（只作信息）。

再按账户过滤：本账户对该链已 `paper_chain_done`（D24）、或该版本已有过订单、或本账户持有该链 → 不可买（标原因，Agent 自管账户看得到但不能买）。

对每个账户再算**本账户的上限股数** `max_shares`：`plans.size` 的三条上限（风险、单票、总仓位）按本账户的权益与参数、已持仓市值、在挂买单的占用算，再受 `max_positions`（持仓数 + 在挂买单数 < 上限才能新开）与现金约束（`cash − 在挂买单占用 ≥ 股数 × 入场上沿 + 费`）；`max_shares ≤ 0` 的项标 `no_room`，照计划执行账户跳过它、Agent 自管账户看得到但不能买。

### 5.2 Agent 自管账户（`agent-portfolio-1`）

#### 5.2.1 证据块（宿主拼好，`[fact:<键>]` 段落，数字不可改）

| 键 | 内容 |
| --- | --- |
| `account` | 名称、参数、现金、权益、自开户收益率、最大回撤、持仓数 / 上限、可新开仓位数 |
| `positions` | 每只：数量、成本、最近收盘、市值、R、有效止损与模式、T1、是否到过 T1、持有 / 最长持有天数、宿主指令（`hold` / `sell_half` / `exit`）与维持理由（即 §6 第 ③ 步写的本账户持仓状态行）、成交那一版（冻结）、所属链在真实层面的最新动态（最近复查结论；链已作废 / 过期时写明日期与原因，D30） |
| `pending_orders` | 在挂买单：链、版本、股数、入场区间、挂单日、到期日 |
| `buyable` | §5.1 的每项 + `max_shares` 与 `sizing_status`；已持有该链的标「已持有，不可加仓」 |
| `rejected_yesterday` | 昨日被宿主拒绝的订单与原因 |
| `recent_closed` | 本账户最近 20 个交易日结束的交易：标的、R、退出原因、持有天数 |
| `market` | `regime-2` 标签、广度、行业强弱 |

#### 5.2.2 提示词要点（`PORTFOLIO_PROMPT`，实施时逐字写进 `graph.py`）

角色：「你管理一个模拟账户，目标是用 Agent 已经给出的交易计划管好一个组合」。规则：只能买 `buyable` 里列出的 `plan_id`，股数 ≤ `max_shares`，价位一律用计划的、不能另定；卖出按次一交易日开盘价成交；止损、T1 卖半、时间止损由程序自动执行，你不能取消，只能更早卖；每条订单与每只持有都要一句理由（≤ 300 字）；可以撤掉自己在挂的买单；不要考虑计划之外的标的。输出：

```json
{"orders": [{"action": "buy", "plan_id": "…", "shares": 60, "reason": "…"},
            {"action": "sell", "ticker": "NVDA", "portion": "all" | "half", "reason": "…"},
            {"action": "cancel", "order_id": "…", "reason": "…"}],
 "holds": [{"ticker": "AMD", "reason": "…"}],
 "summary": "…（1 到 200 字）"}
```

`holds` 必须覆盖每只没有卖出订单的持仓；`buyable` 里没买的不必解释。工具与标的限制见 D11。

#### 5.2.3 宿主校验（逐条，`paper_strategies.validate_orders`）

| 检查 | 失败码 |
| --- | --- |
| JSON 结构、字段类型、`reason` 1–300 字、`summary` 1–200 字、`holds` 覆盖全部未卖持仓 | 整份输出 `rejected`（`schema_invalid`），账户当天不动 |
| `plan_id` ∈ `buyable` 且不在「已持有」 | `plan_not_buyable` |
| 本账户对该链已结束或该版本已有过订单（D24） | `chain_consumed` |
| 同一链已有在挂买单 | `duplicate_order` |
| `shares` 为正整数且 ≤ `max_shares` | `exceeds_max_shares` |
| 持仓数 + 在挂买单 + 本批买单 ≤ `max_positions` | `max_positions` |
| 累计现金占用 ≤ 现金 | `insufficient_cash` |
| `sell` 的标的有持仓；`half` 时股数 ≥ 2 | `no_position` / `cannot_halve` |
| `cancel` 的订单属于本账户且在挂 | `order_not_pending` |

单条失败只拒那一条（存 `paper_orders`，`status = rejected`，`reject_reason`），其余照挂；整份结构失败才整体拒绝。

### 5.3 成交与退出（`paper-fill-1`，`paper_fill.py`，纯函数）

对每个模拟账户，从 `settled_through` 的下一个交易日起**逐日**结算到本 session（D26），每一天 T 用 T 的日线，步骤与规则**与 `plan-shadow-2` 逐字一致**（D28，实施上复用 `plan_shadow.simulate_v2` 抽出的逐日步进函数）：

1. **买单**：`entry_rules.simulate_entry(plan, bars[T])` 的结果：`filled` → 写成交（`trades`，`side = buy`，`price` = 规则给的成交价，`plan_id` = 订单的版本，`recorded_by = host`，`executed_at` = T 开盘时刻（纽约 09:30）或盘中成交按 T 16:00 记，`detail.fill_case` 记 `in_zone` / `gap_up_limit` / `gap_down_stop_buy`）；`voided` → 订单 `status = voided`（原因同 `entry-1`），本链对本账户结束（D24）；`pending` → 继续挂，直到 `valid_until` 过期（`expired`）或链结束 / 换版（`cancelled`，原因）。
2. **宿主退出**（对持仓，含当天刚成交的，按 T 日线）：前一日指令为 `exit`（时间止损、止损触及后未卖出）→ T 开盘卖出全部；当天最低 ≤ 有效止损 → 卖出全部（开盘 ≤ 止损按开盘价 `gap_stop`，否则按止损价 `stop`）；当天最高 ≥ T1 且未到过 T1 → 卖出一半（按 `max(开盘, T1)`），此后止损 = max(开仓以来最高收盘 − 3 ATR, **成交价**)；同一天止损与 T1 都触及按先触止损；时间止损（持有 ≥ `max_hold_sessions` 且从未收盘 ≥ 成交价 + 1R）→ 次日开盘卖出 `time_stop`。卖出成交 `plan_id` = 该持仓冻结的版本（真实账户的卖出可不关联，这里关联以便追溯），`detail.exit_reason` ∈ `stop` / `gap_stop` / `target1_half` / `time_stop` / `agent_sell` / `exit_instruction`。
3. **Agent 主动卖出**：订单 `action = sell` 在 T 开盘价成交（`agent_sell`）；若同日宿主止损也触发，以开盘价卖出记 `agent_sell`（不重复卖）。
4. **持仓的计划**：**冻结在买入成交关联的那一版**（D23），不跟随链的修订；1R 取该版的止损。链被作废 / 过期对持仓的影响见 D30。

费用：每笔 `fee_per_trade`；买入计入成本、卖出从所得扣（与 `positions.build` 一致）。缺 T 日线的标的那天不结算、挂单顺延，`detail.bars_missing` 记下。每结算完一天写该天的权益行并推进 `settled_through`。

### 5.4 照计划执行账户（`follow-plans-1`）

每个交易日 S 收盘后，对 `buyable(S)`（已按 D24 过滤掉本账户消耗过的链与版本）逐项：本账户无该链持仓且无在挂买单 → 若 `max_shares > 0` 挂买单（`shares = max_shares`，`placed_by = host`），否则记一行 `paper_decisions.detail.skipped[]`（`no_room` / `max_positions`）；已有在挂买单但链出了新的入场期版本 → 旧单 `cancelled`（`superseded_by_revision`）、按新版重挂（新版本是新的订单机会，不算 D24 的重复）；链结束（作废 / 过期 / 被取代）→ 撤单。不主动卖出，不对链的作废做反应（D30）。决策记录照写一行（`status = ok`，`model = none`），这样对比页「跳过的 Agent 计划」对它恒为 0 或 `no_room`。

### 5.5 订单与决策记录

- `paper_orders`（§7.5）：一条买 / 卖 / 撤单意图的全生命周期：`pending → filled | voided | expired | cancelled`，或一开始就 `rejected`；每条带 `decision_id`、`placed_on`（S）、成交后的 `trade_id`。
- `paper_decisions`（§7.6）：每个模拟账户每个交易日一行：`status`（`ok` / `skipped` / `rejected`）、`agent_run_id`（Agent 自管）、模型原文输出、`summary`、`holds`、证据块快照 `evidence`（脱敏后的 JSON，供页面「Agent 看到的」与回放）、`detail`（被拒订单计数、`skipped[]`、token 数）。

## 6. `daily` 新节点 `accounts`（`stages-5`、`daily-2`）

`StageDef(id='accounts', title='账户', purpose='结算模拟账户昨天的挂单与退出，给每个账户记一行当日权益，再由照计划执行账户机械挂单、Agent 自管账户决定明天买卖什么。')`，位置 `review` 之后、`push` 之前。非交易日跳过（同其他交易日节点）。

节点体（`service.stage_accounts`）按顺序：

1. **结算**（§5.3）：对每个活跃模拟账户，从 `settled_through` 之后逐交易日结算到本 session（D26）；写成交、订单状态、每天的权益行。一个账户出错只影响该账户（进 `failures`），其余继续。
2. **权益**（§4.3）：真实账户补齐上次有行以来的每个交易日（至少最近 5 个），变了才追加；模拟账户的权益行在第 ① 步里逐日写。
3. **模拟账户的持仓状态**：用 `plan_review._holding_row` 的**无链分支**（冻结的成交版本、宿主判断，D23）对每个模拟账户的每只持仓写 `holding_status`（`account_id` = 该账户），指令与维持理由同口径（宿主模板）。
4. **决策**：照计划执行账户（§5.4）→ Agent 自管账户（§5.2，每账户一次模型调用，记入 `agent_runs`、计入 `WORKBENCH_AGENT_DAILY_TOKENS`，节点自带 `ACCOUNTS_AGENT_DEADLINE_S = 600` 的窗口，D27；不可用按 D12）。

`detail` 记：每账户 `{settled: {filled, voided, expired, cancelled, exits}, equity, holdings, decision: {status, orders_placed, orders_rejected, skipped}}`；运行详情页按账户分块显示；`check`（`plan_review check`）加两项核对：每个活跃账户当天有权益行；每个模拟账户当天有决策行。

续跑：节点失败后从 `accounts` 续跑，①②③幂等（D14），④读回已有决策行、不重调模型。`push`、`retro` 不读本节点的产物（D20），所以本节点失败不影响推送。

| 真实账户未开账 | 不写权益行；建议股数回退快照（D6）；月度回退快照（D16）；页面引导开账 |
| Agent 不可用 / 额度用尽 / 输出不合法 | Agent 自管账户 `skipped` 或 `rejected`（整份），在挂单与宿主退出照常（D12） |
| 某标的缺 S+1 日线 | 该标的的挂单与退出顺延一天，`detail.bars_missing`；权益用最近收盘并标 `stale` |
| 链在挂单期间出新的入场期版本 | 买单 `cancelled (superseded_by_revision)`；照计划执行按新版重挂；Agent 自管账户次日在 `buyable` 里看到新版自行决定 |
| 真实账户买了、链进入持仓期 | 模拟账户不受影响：最新一版入场期版本仍在有效期内就仍可买，过期后自然不可买（D23） |
| 链在模拟持仓期间结束（过期 / 作废 / 被取代） | 模拟持仓按冻结的那一版继续看护（§5.3 第 4 条）；照计划执行不反应，Agent 自管账户在证据块里看到（D30） |
| 漏跑的交易日 | 下次运行逐日补结算与权益行，决策只做当天（D26） |
| 一个账户结算出错 | 只影响该账户（`failures`），其余账户照常；下次运行重试（幂等） |
| 模拟账户现金为负（费用假设导致） | 不应发生（下单前校验）；若出现记 `failures` 并禁止新开单直到为正 |
| 关闭的账户 | 不结算、不决策、不写权益；页面只读 |

## 13. 风险

| 风险 | 缓解 |
| --- | --- |
| 读成交的 ~35 处调用点漏加账户过滤，模拟成交混进链状态 | `list_trades` 缺省真实账户（D4）+ 静态测试列出全部调用点；模拟成交 `recorded_by = host` 可审计 |
| 真实账户开账后权益与你心里的数对不上（费率、拆股、补录） | 对账块逐条列差额；开账前真实库无成交，起点干净 |
| Agent 自管账户每天多一次模型调用，挤占链复查额度 | 节点排在 `review` 之后，复查先用额度；额度用尽则 `skipped`，不反过来挤复查 |
| `paper-fill-1` 的成交假设（按开盘 / 止损价无滑点）过于乐观 | 与影子同假设，页面常驻「模拟成交，无滑点」；`fee_per_trade` 可调；只比较账户之间，不宣称绝对收益 |
| `paper_orders.status` 可更新，违背只追加习惯 | 只允许 `pending → 终态` 一次（应用层 + 更新语句 `WHERE status = 'pending'`）；`updated_at`；决策记录与成交仍只追加 |
| 三个账户起点不同（真实账户开账日与模拟账户不同、金额不同），对比误读 | 对比页归一到各自开户日 = 100 并标开户日；指标表注明「自开户」 |
| `stages-5` 改动节点数，运行一览、守护、详情页的分支 | 同 `stages-4` 升版时的做法，旧运行按 `STAGE_IDS_BY_VERSION` 显示 |

## 14. 已知限制

- 模拟成交是收盘后按日线的纸上成交：无滑点、无部分成交、盘中价位只有开盘 / 最高 / 最低 / 收盘四个点。
- 模拟账户只买 Agent 计划；真实账户里你照规则基线或自定计划买的交易，对比页没有对应物。
- Agent 自管账户同一链只一个买单、不加仓；不能改计划价位（要改走链的修订）。
- 真实账户权益按运行时刻已录入的成交算，补录只重算最近 5 个交易日；更早的补录要手动在「资金」页看对账差额。
- 月度收益率在真实账户开账前仍是快照口径；开账当月两端口径可能不同，页面标 `source`。
- 不做回撤阶梯、不自动降风险；对比表不排名、不判优劣。
- 推送不含模拟账户。
