# v3.2.1 设计：工作台的壳、「纸面」视觉与数据视图

日期：2026-11-09。在 [v3.2 设计](2026-11-08-v3.2-retrospect-research-and-page-polish-design.md)之上；v3.2 的业务（定时研究、对话里发起研究、复盘）**不动**，用户决定让它先跑一段真实运行（v3.2 spec §13 第 3、4 步照旧）。本版只做页面与为页面服务的读接口。版本号 v3.2.1 是用户定的。

## 1. 为什么做这一版

用户的原话：主入口是 agent 对话，偶尔看数据（「进来想看看昨天市场热度」）。现在的页面（v3.1 §12 + v3.2 §10）是反过来的：两栏卡片堆是主体，对话是右下角悬浮按钮打开的外挂面板。三个具体问题：

1. **对话里看不到数据。** agent 每轮调用的工具返回结构化数据（35 个工具都走 `call:N` 信封），但对话面板只渲染文字，工具调用折叠后只剩一个名字；真实的 Pi 运行时没有把 `call:N` 编号带回来（MCP 返回的文本里其实带着 `ref`，只是 `runtime/pi.py` 没去解析），`v3_tool_calls` 只存返回值的哈希。用户问「昨天市场热度」，得到的是一段话，而同一份数据在简报里是一张表。
2. **「抬眼一看」没有位置。** 市场环境埋在简报 Markdown 中段；账户、持仓、今日操作散在两栏里，要滚屏找。
3. **没有性格。** 所有块长得一样，分不清「今天要我做的」和「给我看的」。

讨论过程（2026-11-09，示意图在 `.superpowers/brainstorm/` 下，不入库）：先在「单栏对话台」与「对话 + 仪表栏」两种壳里选了后者；再在「纸面 / 墨线 / 终端」三种视觉里选了**纸面**；随后加了左栏折叠、右侧抽屉（照 Claude Code 桌面版顶栏右侧一组图标开关侧栏的做法）、左栏头部的「快捷入口 / 对话」分段切换并去掉「投资助手」字样、对话区限宽居中。

## 2. 目标、非目标、反目标

**目标**

1. 对话是主体：打开页面就是最近一段对话，左栏能切到对话列表与新开对话。
2. 一个工具一个视图：每个工具的返回有且只有一个视图组件（**快照视图**，画的是调用当时返回的数据）；它与页面、抽屉共用同一批原语（`PlanLevels`、`MetricValue`、`StatusPill`、`DataTable`、`MarketCard`），同一含义全站一个写法。agent 不生成任何 HTML。
3. 对话回合里的工具调用按注册表展开成卡，写入类结果附动作；历史对话重新打开时卡片能回放。
4. 右侧抽屉三面板（仪表 / 行情 / 定时任务）随时开关；左栏快捷入口七项打开完整视图；左栏可折叠。
5. 「纸面」视觉：白底近黑、衬线标题、无阴影、大圆角、分层靠留白与极淡的线；深浅两套。
6. 行情、运行记录、账户流水、工具调用结果有读接口。

**非目标**

- 不改 v3.2 的业务逻辑、每日任务、工具面的工具集合与语义、简报正文。
- 不做图表（K 线、折线）。`get_price_bars` 的视图是表格；图表留到以后按 design-system §8 重建。
- 不做移动端专门设计；窄屏只保证能用（§5.6）。
- 不改认证、不改运行时切换与只读规则。
- 不做对话内的多模态、文件上传、语音。

**反目标**（做成这样算失败）

- 对话里出现模型拼出来的表格或 HTML；卡片的样子由模型文字决定。
- 为了好看丢掉五态：空白、`—`、`null` 又出现在页面上。
- 抽屉和快捷入口放同一份内容的两个版本（抽屉是侧览，完整视图替换中间区域，§5.3）。
- 数字不可追溯：卡片上看不到来源工具、`call:N` 与数据时点。

## 3. 约束

- 技术栈不变：Svelte 5 + Tailwind v4 + Bits UI（shadcn-svelte 的组件层）+ FastAPI + PostgreSQL。**不换框架**（用户确认）；不新增前端运行时依赖（衬线字体用系统字体栈，§6.2）。
- [design-system.md](../design-system.md) 继续是唯一设计规则；本版改它的令牌取值、布局一节、原则 3 的措辞（§6.5）与组件表，**与代码同一个提交更新**。`tests/test_frontend_design_guards.py` 的全部规则继续生效。
- 十六进制令牌（design-system §2）、五态 `DataBlock`、状态词汇表 `status.ts`、`ConfirmDialog` 两步确认（A18）、`request_id` 幂等全部沿用。
- 迁移只追加（036）；`v3_tool_calls` 仍在只追加清单里，只加列不加 `UPDATE`。
- 页面服务不负责定时；「下次运行」从配置推算（§14）。
- 真实库的迁移、前端重建与页面服务重载各需用户单独授权（§15）。

## 4. 做法比较

### 4.1 壳

| 做法 | 说明 | 取舍 |
|---|---|---|
| A 单栏对话台 | 整页对话，顶部一行常驻数据，其余靠提问 | 最干净；「下次开盘卖出」「止损未挂」这类必须处理的事只剩一个数字提醒，易漏 |
| **B 对话 + 侧栏**（选定） | 中间对话；左栏快捷入口与对话列表；右侧可开关的抽屉放抬眼就看的东西 | 必须处理的事始终在视野内；抽屉是注册表组件的第一个消费方；比 A 多一个区域，但可关 |
| C 现状 + 助手升级 | 页面优先，助手面板改好看 | 与「主入口是对话」相反，排除 |

### 4.2 视觉

| 做法 | 说明 | 取舍 |
|---|---|---|
| **纸面**（选定） | 白底近黑、衬线标题、无阴影、12px 卡片圆角、分层靠留白；主按钮墨黑，青绿退出 | 最安静；改令牌与字体栈即可；与原则 3「密度优先」有张力，§6.5 修订 |
| 墨线 | 暖纸底、方角、1.5px 墨线、双等宽字体 | 最有性格；要引入两套字体与一整套线条规则，改动最大 |
| 终端 | 深色默认、等宽数字 | 改动最小；用户没选 |

### 4.3 对话里的数据怎么到前端

| 做法 | 说明 | 取舍 |
|---|---|---|
| SSE 内联 | `tool_end` 帧直接带工具返回的 `data` | 实现最少；历史对话无法回放（消息表只存 `tool_refs`）；一帧可能很大 |
| **落库 + 按编号取**（选定） | 工具面把每次调用的结果写进 `v3_tool_calls.result`；Pi 运行时从工具返回文本里解析出 `call:N`；前端按编号取回渲染 | 历史可回放、简报会话的调用以后也能看；多一次迁移与一个接口；Pi 的解析要靠真实运行确认（§12.2） |

### 4.4 上下文芯片（把页面对象带进对话）

| 做法 | 说明 | 取舍 |
|---|---|---|
| **文字前缀**（选定） | 前端把芯片拼成固定前缀 `[RKLB · 计划 #12] ` 放在问题前；消息原样存、原样给模型；渲染时把前缀识别回芯片 | 不改接口与运行时；模型看到的就是用户看到的；前缀格式固定（§8.4） |
| 接口字段 | `POST messages` 加 `context[]`，宿主拼提示、消息表存结构 | 更干净；要改接口、运行时与消息表，本版不值 |

## 5. 工作台的壳

### 5.1 三栏

```
┌──────────┬──────────────────────────────────────┬──────────────┐
│ 左栏      │ 顶栏：标题 · 数据截至     [▦][∿][◷] | [⚙] │ 右侧抽屉    │
│ [▦|💬] [⫿]│                                      │ 仪表 / 行情  │
│ 快捷入口  │ 中间区域：对话（缺省）或完整视图        │ / 定时任务   │
│ 或 对话   │                                      │              │
│          │ 快捷提问芯片 + 输入框                   │              │
└──────────┴──────────────────────────────────────┴──────────────┘
```

宽度：左栏展开 208px、折叠 56px；抽屉 288px、关闭 0；中间自适应。中间区域的对话与输入框**限宽 760px 居中**（Claude、Manus 的做法；抽屉关掉后气泡不会飘到最右）。完整视图不限宽（表格需要宽度），内边距与对话一致。

### 5.2 左栏

- **头部**：左边一个两格分段切换「快捷入口 / 对话」（图标：四宫格、对话气泡），右边折叠按钮。没有产品名字样。
- **快捷入口**（七项，顺序固定）：今日、账户、行情、计划与持仓、研究、复盘、定时任务。每项图标 + 文字 + 可选数量角标（今日 = 今日操作条数；计划与持仓 = 持仓 + 待入场；研究 = 观察中）。当前项高亮。点击把对应完整视图放进中间区域（§9）。
- **对话**：顶部「新开对话」；列表按「今天 / 本周 / 更早」分组（按最后一条消息时间的北京日期，§11 的 `last_message_at`）；标题是首条用户消息的前 30 个字（§12.4），没有消息的显示「新对话」；只读对话标「只读」；当前对话高亮。点击切换中间区域为该对话。
- **折叠**：分段切换竖排成两个图标；快捷入口只剩图标，有角标的项显示一个小圆点；对话面只剩一个「+」（新开对话）。折叠状态存 `localStorage`，缺省展开。

### 5.3 顶栏与抽屉

- 顶栏左侧：中间区域的标题（对话标题或视图名）· `数据截至 {session}`（没有运行记录时写「还没有运行记录」）。
- 顶栏右侧一组图标按钮：**仪表、行情、定时任务**，一条分割线，**设置**。三个面板按钮是互斥开关：点哪个开哪个；点亮的那个再点一次关掉抽屉。抽屉开着时按 `Esc` 不关它（`Esc` 留给浮层）。抽屉状态（开 / 关、哪个面板）存 `localStorage`，缺省开「仪表」。
- 抽屉是**侧览**：只放看一眼就走的内容，不放表单；每行的动作要么是一个主按钮（如「记成交」），要么是「带进对话」。抽屉与左栏同名项**不是同一份内容**：左栏打开完整视图（替换中间区域），抽屉不离开对话。
- 设置仍是右侧 `Sheet`（`SettingsSheet` 不变）。

### 5.4 路由

hash 路由扩成：

| hash | 中间区域 |
|---|---|
| `#`（空）| 最近一段对话；没有对话时是「新开对话」的空态（一句说明 + 快捷提问芯片） |
| `#chat/{chat_id}` | 该对话 |
| `#today` `#account` `#market` `#plans` `#research` `#retrospect` `#jobs` | 七个完整视图 |
| `#plans/{plan_id}` `#research/{research_id}` | 对应视图并展开该对象（卡片上的「看变化记录」跳这里） |
| `#_ui` | 组件画廊（开发模式） |

未知 hash 回到 `#`。`router.ts` 的 `Route` 从两个值扩成上表；浏览器前进后退可用。

### 5.5 键盘与焦点

- `⌘/Ctrl + K`：聚焦输入框（在任何视图下都切回最近对话并聚焦）。
- `Esc`：关闭最上层浮层（对话框、Sheet、Popover）；没有浮层时不做事。
- 分段切换、快捷入口、抽屉按钮都是真正的 `<button>` / `<a>`，`aria-pressed` / `aria-current` 标明状态。

### 5.6 窄屏（< 1024px）

- 左栏变成从左滑出的 `Sheet`（顶栏左侧一个菜单按钮打开）；抽屉变成从右滑出的 `Sheet`（顶栏右侧同一组图标打开）。两者同时只开一个。
- 中间区域满宽；对话限宽规则自然失效。
- < 768px 继续沿用 design-system §3 的行转卡。

## 6. 「纸面」视觉

### 6.1 令牌取值

只改取值，不加新令牌名（design-system §2 的名字集合不变）。两套都要过 `tokens.test.ts`（集合一致、十六进制、状态色对 `--card` 的 AA）。

| 令牌 | 浅 | 深 | 说明 |
|---|---|---|---|
| `--background` | `#fafafa` | `#0f0f0f` | 左栏、抽屉、顶栏的底 |
| `--card` | `#ffffff` | `#171717` | 中间区域与卡片 |
| `--muted` | `#f2f2f2` | `#222222` | 气泡、当前项、悬停 |
| `--border` | `#ececec` | `#2a2a2a` | 唯一的线；卡片描边也是它 |
| `--input` | `#e0e0e0` | `#3a3a3a` | 输入框与描边按钮 |
| `--ring` | `#1a1a1a` | `#ededed` | 焦点圈 |
| `--foreground` | `#1a1a1a` | `#ededed` | |
| `--muted-foreground` | `#6b6b6b` | `#9a9a9a` | 次要文字（对 `--card` ≥ 4.5:1） |
| `--primary` / `-foreground` | `#1a1a19` / `#ffffff` | `#ededed` / `#111111` | 主按钮、当前导航；青绿退出 |
| `--popover` 等 | 随 `--card` | 随 `--card` | |
| 状态色 `--success` 等六组、`--up` / `--down`、`--chart-*` | **不变** | **不变** | 已过 AA |
| `--shadow-1` / `--shadow-2` | 只给浮层（Popover、Sheet、Dialog） | 同 | 卡片、按钮、输入框**不投影** |
| `--radius` | `8px` | | 控件（`rounded-sm/md/lg` 仍映射到它）；`app.css` 新增 `--radius-xl: 12px`（卡片、输入框）、`--radius-2xl: 14px`（用户气泡）；`rounded-full` 不变。design-system §2「其余 `rounded-*` 映射到同一个值」改为这三档；`tokens.test.ts` 的 6px 断言改 8px |

### 6.2 字体

- 正文与界面：现有 `Inter` + 中文系统字体栈，不变。
- **标题**（卡片标题、面板标题、视图标题、对话标题）：新增 `--font-serif`：`"Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", Georgia, serif`，字重 600。页面服务跑在本机 Mac 上，Songti SC 必有；其他平台退到系统衬线。**不加字体依赖**。
- 数字：继续 `tabular-nums`（`.tabular` / `MetricValue`）。来源行（工具名、`call:N`）用等宽（`CalcVersion` 同款）。

### 6.3 线条、层次与状态

- 分层顺序：`--background`（栏）→ `--card`（纸面）→ `--muted`（选中 / 气泡）。栏与中间区域之间一条 `--border`。
- 卡片：`--card` 底 + 1px `--border` + 12px 圆角，无阴影。
- 用户气泡：`--muted` 底、14px 圆角、靠右；助手不是气泡，是正文（上方一行「助手」的次要文字）。
- 状态徽标 `StatusPill` 外观不变（圆点 + 文字 + 淡底），只是底色随 `--muted`。
- 按钮：`primary` 墨黑；`outline` 1px `--input`；`ghost` 悬停 `--muted`。

### 6.4 深色

深色是同一套结构的「黑纸」：`--background #0f0f0f`、`--card #171717`，主按钮反色。切换方式与 `lib/theme.ts` 不变。

### 6.5 对 design-system 原则 3 的修订

原文「密度优先……默认紧凑密度，一屏尽量多放信息」改为：**「视图与抽屉紧凑，对话从容。」** 表格、卡片、抽屉继续紧凑密度（行高、字号不变）；对话区正文 13px / 行高 1.55、限宽 760px、回合之间 14px，不为塞更多信息压缩。

## 7. 组件规范：数据视图注册表

### 7.1 概念

`web/src/lib/views/registry.ts`：一张表，键是**工具名**（裸名，不带运行时前缀），值是 `{ component, title(data), props(data) }`。对话里拿到一份工具返回（`call:N`）就通过注册表渲染，不自己拼。

**快照与现状。** 工具返回的是调用当时的数据（计划是 `v3_plans` 原始行，没有页面卡片的 `position` / `next_action` 等推导字段）。注册表的视图画的就是这份快照，页头注明时点；卡片上的动作按对象 id 走页面接口取**现在**的状态（例如「打开计划」跳 `#plans/{id}`，「记成交」用 id、股票、股数预填表单后走现有流程）。历史回放看到的因此是「当时」，这是有意的。

- 注册表**必须覆盖全部 35 个工具**：有专属视图的用专属组件；其余落到**通用视图**（§7.3），保证每次调用都有一张卡，没有「暂无调用编号」这样的空壳。
- 每张卡的页头固定三样：标题（衬线）、状态徽标（如有）、**来源行**（等宽次要文字）：`{tool} · call:{N} · {session 或 时点}`。这是 design-system 原则 2「数字可追溯」在卡片上的落地。
- 五态照旧：取数中 `loading`、工具返回 `error` 信封 → `error` 态并显示中文映射；返回空列表 → `empty` 并写为什么空；`not_computed` 来自数据本身（缺价位、缺样本）。

### 7.2 专属视图

## 8. 对话

### 8.1 回合结构

一轮 = 用户消息 + 助手回合。助手回合由三类块按事件顺序组成：

- **文字**：流式追加；
- **工具卡**：`tool_start` 时先放一张「调用中」占位（标题 = 工具中文名，来源行 `{tool} · 调用中`；工具名是裸名，§12.2），`tool_end` 带 `ref` 后按 `call:N` 取回结果并换成注册表视图；`ref` 为空（§12.2 解析失败）时显示「调用已完成，结果不可追溯」的 `degraded` 态卡；
- **动作**：写入类卡片自带的按钮（§8.3）。

助手文字里的 `fact:` / `call:` 引用继续走 `RefLink`：`call:N` 可点，点了滚动到对应卡片并高亮一下。

### 8.2 历史回放

`GET /api/chats/{id}` 的消息现在带 `agent_session`（§11），`tool_refs` 在 Pi 下也会有值（§12.2）。打开历史对话时，每条助手消息按 `tool_refs` 取回各卡（并发、按需：进入视口才取）。消息表不存文字与卡片的交错位置，回放时**卡片统一放在该条文字之上**（agent 的常态是先查后说）；直播时按事件顺序。`ref` 为空的调用历史里没有记录，不出现。取卡失败不影响文字显示。

### 8.3 动作

卡片上的动作**只复用页面已有的写入流程**，不新开口子：`PlanCard` 的记成交 / 确认止损单 / 上调止损 / 作废；`ResearchCard` 的放弃研究；`AccountCard` 的记出入金 / 对账。都是 `confirmed=false` 拿 `preview` → `ConfirmDialog` → `confirmed=true`。动作完成后触发全站 store 失效重取（§10）并 `notify.success`；当前回合下追加一行只在本页存在的说明「已记成交：RKLB 卖出 120 股 @ $45.10」（不落库，刷新即无；消息表的 `role` 不扩）。

### 8.4 上下文芯片

- 来源：抽屉与视图里每个对象行的「带进对话」；对话里卡片页头的「就这个继续问」。
- 对象三种：`ticker`、`plan:{id}`、`research:{id}`。
- 前端把芯片拼成固定前缀放在输入文字前，格式逐字：`[{TICKER}] `、`[{TICKER} · 计划 #{id}] `、`[{TICKER} · 研究 #{id}] `，多个芯片依次排列。消息按原文发送与存储。
- 渲染用户消息时，把开头连续的 `[…] ` 识别回芯片样式（不改变文字内容）。识别规则只认这三种格式。
- 输入框上方显示当前挂着的芯片，可删除；发送后清空。

### 8.5 快捷提问

输入框上方一排芯片，固定五个，点击把句子填进输入框并发送：「昨天市场热度」→ `昨天的市场热度怎么样？`、「今日操作」→ `今天我要做什么？`、「持仓怎么样」→ `持仓现在什么情况？`、「待入场名单」→ `待入场的计划有哪些？`、「发起研究…」→ 只预填 `研究 `，不发送（v3.2 §6.2 的入口）。

### 8.6 运行中、取消、忙碌

沿用现状：一轮可取消；`brief_running` / `chat_running` / `no_run` / `chat_read_only` 的提示文案不变；关掉抽屉或切视图不打断流式中的一轮（对话组件常驻不卸载，和现在的助手面板一样）。切到另一段对话时，当前轮的 SSE 连接由对话组件保持，继续跑完并存库，回来能看到；刷新或关页面仍会取消这一轮（`api/routes/chats.py` 断连即取消，现状不变）。

每个视图 = `PageHeader`（衬线标题 + 口径 / 时点）+ 若干段。它们只组合注册表里的组件与现有组件，不自己拼样式。

## 11. 页面接口的变化

全部是读接口，形状如下（名称留给实施者的只有查询参数名）：

| 接口 | 返回 |
|---|---|
| `GET /api/market` | `{ session, calc_version, label, regime_tier, breadth{…}, spy_ret20, etf_table[…], macro{…}, watch[{ ticker, last_close, prev_close, change_pct, source: 'holding' \| 'pending' \| 'research', plan_id, research_id }] }`：最新一次成功运行的 `v3_runs.market` 原样 + `session`；`watch` 是持仓、待入场、观察中研究的股票并集（按此顺序去重），`last_close` / `prev_close` 取 `price_bars` 最近两根，缺日线时两者为 null、`change_pct` 为 null；没有运行记录 404 `no_run` |
| `GET /api/runs?limit=20` | `{ schedule{ weekdays[], hour, minute, tz, next_at }, runs[{ session, trigger, status, error, started_at, finished_at, brief{ status, error, unfinished, runtime, provider, model, usage, elapsed_seconds, pushed_final_at, pushed_error_at, weekly: {present, pushed_at} } }] }`：`v3_runs` 按 `session` 倒序，`v3_briefs` 按 `session` 左连接；`next_at` 由 §14 的配置推算（北京时间），`started_at` 等照旧 ISO |
| `GET /api/ledger?limit=20` | `{ trades[…], cash_flows[…], equity[…], voids[…] }`：四张表各最近 `limit` 行，金额字符串；`trades` / `cash_flows` 行带 `voided_by`（作废记录 id 或 null）与 `void_reason` |
| `GET /api/chats/{chat_id}/calls?agent_session=…&ref=call:N` | `{ ref, tool, args, result, error, called_at, truncated }`；没有这一行 404 `unknown_call`；`agent_session` 不属于该对话 404 `unknown_call` |
| `GET /api/chats`（改） | 每行多 `last_message_at`（最后一条消息的 `created_at`，没有消息时等于 `created_at`）；按它倒序 |
| `GET /api/chats/{chat_id}`（改） | 消息行多一个 `agent_session`（助手行有值，用户行 null）；`chat.title` 由 §12.4 写入 |
| `POST /api/chats/{chat_id}/messages`（改） | SSE 第一帧是宿主发的 `event: start`，`data: {"kind":"start","agent_session":"chat-…-{seq}"}`；其后不变 |
| `GET /api/today`（改） | 多一个 `counts{ actions, holdings, pending, watching }` 给左栏角标，免得左栏开三个请求 |

新路由仍在 `create_app()` 的两个兜底路由之前注册；错误格式、Basic 认证、Decimal 序列化沿用 `api/deps.py`。

## 12. 宿主与工具面的变化

### 12.1 结果落库

`toolsurface/dispatch.py::_finish` 把 `payload`（成功）或 `error` + `detail`（失败）写进 `v3_tool_calls.result`（JSONB）。序列化后超过 **512 KB** 的只存 `{"truncated": true, "bytes": n}` 并把 `truncated` 置真；哈希仍按完整 payload 算（现有行为不变）。`brief` 与 `chat` 两种模式都存。写记录失败不影响返回（现有规则）。

### 12.2 Pi 的 `call:N` 与工具名

工具面经 MCP 返回的文本就是完整信封（`toolsurface/jsonrpc.py`），里面有 `"ref": "call:N"`。`runtime/pi.py` 改两处：

- `tool_execution_end` 事件的 `result.content[].text` 里第一段能解析成 JSON 且带 `ref` 的，取出来填进 `RuntimeEvent.ref`；解析不到就留空（前端显示「结果不可追溯」）。不按顺序猜。
- Pi 的 `toolName` 带运行时前缀（`mcp__ia__get_agenda`，前缀来自 `runtime/mcpconfig.py` 的服务名）：`tool_start` / `tool_end` 的 `tool` 一律去掉前缀后再发，`v3_tool_calls.tool`、注册表键、占位卡标题都用裸名。

`tests/fixtures/pi_events/*.jsonl` 是手写的、没有 `ref`：实施时补一份带信封文本的 fixture；事件的真实形状以 `docs/operations/pi-unattended.md` 记录的样本为准，上线冒烟（§15 第 3 步）用真实 Pi 验证。`FakeRuntime` 已带 `ref`，不动。

### 12.3 不动的与一处例外

工具集合、每个工具的参数、`mode` 划分、`_record` 的哈希、`v3_tool_calls` 的只追加约束都不动。返回只有一处**追加**：`get_market` 的返回多一个 `calc_version`（来自 `v3_runs.market`），其余字段不变。

### 12.4 对话标题与最后活动时间

`runtime/chat.py` 在写入首条用户消息（`seq == 1`）时把 `v3_chats.title` 写成该消息前 30 个字（超出加「…」）；每次写入消息后刷新 `v3_chats.updated_at`。`/api/chats` 的 `last_message_at` 由消息表聚合得出，不依赖 `updated_at`。已有的空标题对话由前端显示「新对话」。

## 13. 数据（迁移 036，可重跑）

```sql
ALTER TABLE v3_tool_calls ADD COLUMN IF NOT EXISTS result JSONB;
ALTER TABLE v3_tool_calls ADD COLUMN IF NOT EXISTS truncated BOOLEAN NOT NULL DEFAULT FALSE;
```

历史行 `result` 为 NULL：前端对 NULL 显示「这次调用早于 v3.2.1，没有保留结果」的 `empty` 态卡。不回填。

## 14. 配置

`V3Config` 新增四个键（配置 JSON 的 `v3` 段，`config.py::_validate_v3` 校验范围）：

| 键 | 缺省 | 范围 | 用途 |
|---|---|---|---|
| `daily_weekdays` | `(2, 3, 4, 5, 6)` | 1–7 的子集，非空 | 与 LaunchAgent 模板一致（周二至周六） |
| `daily_hour` / `daily_minute` | `11` / `30` | 0–23 / 0–59 | 北京时间 11:30 |
| `tool_result_max_bytes` | `524288` | [65536, 8388608] | §12.1 的截断阈值 |

`next_at` 的推算：从「现在（北京时间）」起找下一个落在 `daily_weekdays` 内、时刻为 `daily_hour:daily_minute` 的时间点。配置与 plist 不一致时页面显示的下次运行就是错的，`docs/operations/daily-run.md` 里写明两处要一起改。

## 15. 上线步骤（每一步都需要用户单独授权）

1. 备份真实库，执行迁移 036（`docs/operations/migrations-and-backup.md` 的流程）。
2. `cd web && npm run build` 重建 `web/dist`，`launchctl kickstart -k` 重启页面服务。

4. 通过后在 CHANGELOG 记 v3.2.1；roadmap 的 v3.2 一行加一句。
