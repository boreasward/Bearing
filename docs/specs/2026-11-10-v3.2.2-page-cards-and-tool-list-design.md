# v3.2.2 设计：「今日」「账户」的卡片化与工具面板

状态：用户已批准（2026-11-10），待实施。在 v3.2.1 的三栏工作台之上做交互优化，不加新业务能力。

## 1. 为什么做这一版

用户的原话（2026-11-10）：

1. 「今日、账户」页面的内容很杂并糅合在一起，希望以卡片形式存在：账户卡片、行情卡片；不同数据可以看到边界。
2. agent 优化：右侧能有个 list 展示 agent 能够调用的 tool 列表以及功能描述。

现状里造成「糅合」的三处：

- 「今日」页的简报是一篇 markdown（`facts/brief.py` 的 `render_brief`，十个小节），`BriefPanel` 把它原样连着渲染，小节之间只有一行标题。
- 简报里的「今日操作」「账户」「市场环境」三节，页面上另有一份数据（`TodayActions`、`AccountStrip`、行情页的 `MarketCard`），同一件事出现两次。
- 「账户」页只有顶部的 `AccountCard` 是卡片；成交、出入金、对账三张表是没有边框的 `Section`，「记成交」按钮悬在两段之间。

工具方面：35 个工具定义在 `toolsurface/dispatch.py`，页面上没有任何地方能看到 agent 手里有什么。

## 2. 目标、非目标、反目标

**目标**

1. 「今日」页：简报的每个小节是一张有边框的卡；左边一栏放要读的文字卡，右边一栏放账户与行情两张数字卡。
2. 「今日」页的卡片跟着所选简报的日期变（用户决定）；账户卡例外，始终显示最新数字（用户决定）。
3. 「账户」页：概览、持仓、成交、出入金、对账各一张卡，按钮在它所属的卡里。
4. 右侧抽屉加第四个面板「工具」：只读，列出对话里可调用的 35 个工具，每个带中文名、工具名、一句给人看的说明（用户决定：只看说明，不能点了发起对话）。

**非目标**

- 不改简报的文字、小节顺序、Discord 推送与 `reports/` 下的文件。
- 不改行情、计划与持仓、研究、复盘、定时任务五个视图，不改抽屉已有的三个面板。
- 工具面板不做搜索框、不做点选预填、不显示工具的参数、不区分「简报模式也用」。
- 不加迁移，不动工具面（`dispatch.py` 的 35 个定义与描述原样）。
- agent 方面这一版只做工具面板一条（用户确认）。

**反目标**（做成这样就算失败）

- 历史简报打不开，或某个小节在页面上丢了。
- 同一份数据在「今日」页上出现两次。
- 工具面板列出的工具与对话里实际可调用的不一致。

## 3. 约束

- 简报在库里只有 markdown（`v3_briefs.final_md` / `draft_md`），没有结构化副本；已有的历史简报必须照常显示。
- 每次运行存了当天的市场快照（`v3_runs.market`）。简报里「市场环境」一节的数据就是它（`facts/view.py` 取 `run.get("market")`），`/api/market` 读的也是它。简报行有 `run_id`。
- 页面不用 `{@html}` 渲染 markdown（`Markdown.svelte` 的既有约束）。
- 卡片样式沿用设计标准：`Card.Root`、1px 边框、12px 圆角、无阴影；不引入新的颜色或层次。
- 抽屉宽 288px；窄屏（< 1024px）抽屉是右侧 `Sheet`。

## 4. 做法比较

### 4.1 简报怎么变成卡片

| 做法 | 内容 | 取舍 |
| --- | --- | --- |
| 前端按标题拆 | 后端不动，前端按 `##` 切 markdown | 最小；但前端要认得标题文字，后端改一个字就对不上；行情卡只是普通列表加表格 |
| **后端分节，行情卡用当天快照**（选定） | 简报接口多返回带固定名字的小节与当天的市场快照；拆分逻辑与 `render_brief` 同文件 | 历史简报全部可用、不需要迁移；行情卡复用 `MarketCard`，有涨跌颜色与状态徽标；多改一个接口 |
| 整份存结构化数据 | 加迁移，每份简报存结构化副本，所有卡片用专门组件 | 改动最大；历史简报没有副本，仍要留按文字显示的退路；持仓、计划几节本来是 agent 写的叙述，收益有限 |

用户选定第二种（2026-11-10）。

### 4.2 工具说明放哪

| 做法 | 内容 | 取舍 |
| --- | --- | --- |
| **放前端**（选定） | 在 `views/labels.ts` 的中文名表旁边加说明与分组的表 | 不需要接口；`Record<ToolName, …>` 让类型检查强制每个工具都有；以后加工具要同时改这张表（现在加工具本来就要改注册表与中文名） |
| 放后端 | `ToolDef` 加给人看的说明与分组，新增接口返回列表 | 面板显示的就是真实工具面；多一个接口与一组测试 |

用户选定放前端（2026-11-10）。反目标第三条由测试守住（§7.4）。

## 5. 「今日」页

### 5.1 布局

宽度够时两栏（用户从三张示意图里选定「左文字，右数字」）：

```
┌ 今日 ───────────────────────────── [2026-11-09 ▾] ┐
│ ┌ 今日操作 ───────────────┐  ┌ 账户（最新）──┐   │
│ └─────────────────────────┘  │ 现金 总资产   │   │
│ ┌ 一句话 ─────────────────┐  │ 浮动 已实现   │   │
│ └─────────────────────────┘  │ [记出入金][对账]│  │
│ ┌ 和昨天比变了什么 ───────┐  └───────────────┘   │
│ └─────────────────────────┘  ┌ 行情 ─────────┐   │
│ ┌ 持仓 ───────────────────┐  │ 区制 广度 SPY │   │
│ └─────────────────────────┘  │ ETF 表        │   │
│ ┌ 待入场计划 ─────────────┐  └───────────────┘   │
│ ┌ 研究 ───────────────────┐   （右栏滚动时固定） │
│ ┌ 规则名单 ───────────────┐                      │
│ ┌ 今天下不了结论的 ───────┐                      │
│ 数据截至 …（页脚一行，次要文字）                  │
└──────────────────────────────────────────────────┘
```

- 左栏自适应，右栏定宽（建议 320px，实施者可在 288–340px 间按 ETF 表不折行调整）。右栏在中间区域滚动时固定在顶部。
- **放不下时**（抽屉打开或窗口较窄，中间区域不足以让左栏保持约 480px）：账户与行情两张卡挪到最上面并排，下面是文字卡单列；再窄（放不下两张并排）时全部单列，账户、行情仍在最前。这一条是我定的，用户看过示意图未提异议。按中间区域的实际宽度判断，不按视口宽度（抽屉开关会改变它）。
- 日期选择器从简报块里挪到页面标题行右侧，管所有「当日」卡片；只有一份简报时不显示。`#today?session=YYYY-MM-DD` 的深链照旧。

### 5.2 卡片清单

| 位置 | 卡片 | 数据 | 说明 |
| --- | --- | --- | --- |
| 左 | 今日操作 | 见 §5.3 | |
| 左 | 一句话 | 小节 `summary` | 草稿没有这一节，不出卡 |
| 左 | 和昨天比变了什么 | 小节 `changes` | |
| 左 | 持仓 | 小节 `holdings` | |
| 左 | 待入场计划 | 小节 `pending` | |
| 左 | 研究 | 小节 `research` | 简报没有这一节时不出卡 |
| 左 | 规则名单 | 小节 `candidates` | 卡片标题用「规则名单」，不用简报里的长标题 |
| 左 | 今天下不了结论的 | 小节 `unresolved` | |
| 右 | 账户 | `/api/today` 的 `account`（最新） | 现有 `AccountStrip` 的内容与两个按钮；选中的不是最新一份简报时，标题旁加次要文字「最新」 |
| 右 | 行情 | 简报接口的 `market`（当天快照） | 见 §5.4 |

- 文字卡的正文用现有 `Markdown` 渲染该小节的 markdown（不含 `##` 标题行，标题在卡片标题里）。
- 简报的「账户」小节（`account`）页面上不显示：右栏已有最新的账户卡。接口仍返回它。
- 接口返回了前端清单之外的 `key`（以后简报加了新小节而页面还没跟上）时，按它的标题在左栏末尾出一张文字卡，不丢内容。
- 草稿的「二次确认未完成」提示保留现在的 `Alert`，放在左栏最上面；只在 `status` 为 `draft` 时显示。现在出错的简报也会带上这一条（`unfinished` 对 `error` 也为真），这一版去掉。
- 页脚（「数据截至……不构成投资建议……」）在所有卡片之下，一行次要文字，不进卡。
- 出错的简报（`status` 为 `error`）没有任何小节：左栏最上面只有一条危险 `Alert`，文字用 `lead`（「今天无法检查止损：……」或「今天没有简报：……」，它已经包含原因）；`lead` 为空时退回现在的 `error` 文案。不另出「简报」卡，同一段原因不出现两次。今日操作按 §5.3；账户卡照常；行情卡显示空态「这一天没有市场数据」，不退到别的日期的快照。这一条是我定的。
- 还没有任何简报时：左栏是「今日操作」加一句空态原因（沿用现有文案）；账户卡照常；行情卡用 `/api/market` 的最新快照（此时没有选中的日期，不冲突），也没有时显示空态原因。

### 5.3 今日操作只留一份

- 选中的是最新一份简报（或还没有简报）：用现有 `TodayActions`（`/api/today` 的实时操作，带「记成交」「确认已挂单」「带进对话」），空时是现有的「今天没有需要操作的事项」。简报里的 `actions` 小节不显示。
- 选中的是历史简报：显示那天的 `actions` 小节文字，没有按钮；那天没有这一节时卡片正文写「当天没有需要操作的事项」。

「最新一份」指简报列表（`/api/briefs`）里的第一条。这一条是我定的：历史上的操作按钮已经不能点，留着会误操作。

### 5.4 行情卡

- 标题「行情」（`MarketCard` 现在标题写死「市场温度」，要能改）。有当天快照时显示：区制徽标、交易日、广度（50 日 / 200 日）、52 周新高新低、SPY 20 日、ETF 表（全部行，原顺序，行上没有「带进对话」）；不带宏观与关注标的。
- 现有三种形态都不完全对：缺省形态只有前 6 行 ETF；`pane` 形态不显示 200 日广度与 SPY 20 日、ETF 行带按钮并按 RS20 排序、还带关注表（那是「现在的关注列表」，和简报当天的数据混在一起）。给 `MarketCard` 加一个形态还是调整参数由实施者定；对话快照、行情页与抽屉里的三种现有用法外观不变。
- 卡片底部一个链接「打开完整行情 ›」（`#market`，那里永远是最新的）。
- 页面接口不带 `meta`，不显示来源行（与行情页一致）；有 `calc_version` 时显示口径。
- 当天快照取不到（`market` 为 `null`）时，行情卡退回显示简报「市场环境」小节的文字，仍是一张卡；连这一节也没有（出错的简报）时显示空态「这一天没有市场数据」。

五张卡，自上而下：

- 对话里的账户快照卡（`get_account`、`record_cash_flow`、`record_equity` 用的 `AccountCard`）外观不变。页面的概览卡与持仓卡是从它抽出共用部分还是另写，由实施者定。

## 7. 工具面板

### 7.1 位置

右侧抽屉的第四个面板「工具」：顶栏右侧图标组在「定时任务」之后加一个扳手图标，与另外三个互斥开关；状态照旧存 `localStorage`（`ws.drawer` 多一个取值 `tools`）；窄屏下同样走右侧 `Sheet`。位置是我提的，用户看过示意图未提异议。

### 7.2 内容

- 标题下一行次要文字：「助手在对话里能调用的 35 个工具」（数字从表里算，不写死）。
- 五组，每组标题带个数，可折叠，缺省全部展开；折叠状态不持久化。
- 每个工具一行：中文名（`TOOL_LABELS`）、等宽小字的工具名、一句说明；会改数据的在右侧带标记：
  - 「写入」：agent 直接写。
  - 「写入 · 先确认」：先复述，用户确认后才写。
- 只读：行不可点，没有「带进对话」。

### 7.4 一致性由测试守住

- 说明、分组、写入类型是一张 `Record<ToolName, …>`（`ToolName` 与 `TOOL_NAMES` 在 `views/registry.ts`），漏一个工具类型检查不过。
- 前端测试：写入类型不是「—」的工具集合等于 `views/tool-write.ts` 的 `isMutatingTool` 集合（19 个）；每组个数与本节一致，合计等于 `TOOL_NAMES` 的长度。
- 工具名与后端一致已有间接保证，不重复写：后端 `tests/test_tool_result_fixtures.py` 断言 `tool_defs('chat')` 等于共享 fixtures 的文件名（35 个），前端 `views/registry.test.ts` 断言 fixtures 与 `REGISTRY` 一致。
- 新写一条后端测试：参数里有 `confirmed` 的工具集合等于前端工具表里标「先确认」的集合。它要读前端源码；`tests/test_dashboard_frontend_source.py` 目前只查文件存在与少量文本，没有解析 TS 常量的先例，所以工具表每个工具写成一行、格式固定，方便用正则读。

## 8. 页面接口的变化

只改简报的两个读接口，其余不动；不加新接口。

`GET /api/briefs/latest`、`GET /api/briefs/{session}` 在现有字段之外多返回：

| 字段 | 形状 | 含义 |
| --- | --- | --- |
| `sections` | `[{ key, title, markdown }]`，按简报里的顺序 | 每个已知小节一项；`markdown` 不含标题行。`key` 取 `actions`、`summary`、`changes`、`market`、`holdings`、`pending`、`research`、`candidates`、`account`、`unresolved` |
| `lead` | `string \| null` | 标题行之后、第一个小节之前的文字，去掉固定的一行「二次确认未完成」（它由 `status` 表达）；出错的简报里是那段原因说明 |
| `footer` | `string \| null` | 全文最后一段，且以「数据截至」开头时才算 |
| `market` | 对象或 `null` | 这份简报的 `run_id` 对应运行的 `v3_runs.market`，另带 `session` 与 `calc_version`，形状同 `/api/market` 去掉 `watch`；`run_id` 为空、运行不存在或快照为空（出错的运行写的是 `{}`）时为 `null` |

- 现有的 `markdown`、`status`、`unfinished` 等字段保留不变。
- **只按已知标题切**：一行恰好等于「`## ` + 表里的某个标题」才开始一个新小节；其他以 `## ` 开头的行（agent 写的一句话、复查理由、研究结论里可能出现）留在所在小节的正文里。这一条是我定的。
- 标题到 `key` 的对应表与拆分函数放在 `facts/brief.py`，紧挨 `render_brief`：`render_brief` 用的小节标题从同一张表取，以后加小节或改标题时两边一起变。已经存下的旧简报用的是现在这组标题（v3.1 以来没变过，v3.2 加了「研究」），照常能拆。
- 拆分是纯函数，输入一篇 markdown，输出 `lead`、`sections`、`footer`；`markdown` 为空串时三者为 `null`、`[]`、`null`。
- 按 `run_id` 取一次运行需要在 `facts/repo.py` 新写一个读函数（现有的 `latest_ok_run` 取的是最新一次成功运行，不是简报对应的那次；`run_id` 是字符串列）。
