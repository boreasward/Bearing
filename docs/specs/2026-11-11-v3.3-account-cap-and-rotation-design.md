# v3.3.0 设计：账户维度——仓位上限与换仓比较

> 状态：待用户批准。写成后只增不改。
> 与 [v3.1 设计](2026-11-06-v3.1-plan-line-account-and-web-design.md)、[v3.2 设计](2026-11-08-v3.2-retrospect-research-and-page-polish-design.md) 的关系：本文在计划线、止损纪律、账户、复盘之上加一层账户维度的判断。两份设计没被本文改动的部分仍然有效；改动之处列在 §16，冲突时以本文为准。
> 文中「用户决定」是用户在 2026-11-11 的讨论里明确说的；「我的判断」是设计者替用户做的默认选择，用户可以推翻；两者不混写。
> 文中 A 指一只已买入的持仓，B 指当天通过二次确认的候选。

---

## 1. 为什么做这一版

**用户原话（2026-11-11）**

- 「目前 agent 主要围绕"交易计划"：生成、过期、替换；但是缺乏账户维度判断；例如：股票 A 在持仓中，股票 B 进入候选池，但是是否需要用 B 替换 A 的仓位呢？」
- 问到希望简报怎么说：「继续拿着 A，还是半仓替换 B、全仓替换 B。」
- 问到半仓和全仓的分界：「取决于 B 比 A 强多少，是否值得冒险加仓 B。」
- 问到怎么判断强弱：「交给 agent 综合判断即可，因为我的经验只是亏钱的经验。」
- 问到钱够的时候还比不比：「钱够就直接买 B，不够时再和 A 比；但是我觉得满仓是很危险的。」
- 对总仓位上限 60%：「可以，先用 60% 起步。」
- 问到刚买两天的 A 参不参与比较：「比，出发点：假设我当时看错了，现在看到一个更合适的 B；但是我很担心这样会频繁换仓导致交易成本磨损。」
- 对频率：「可以，每 5 个交易日最多一次。」
- 对做法：选方案一（§4）。

**2026-11-11 对现有代码的核实**

| 现象 | 依据 |
|---|---|
| 替换只发生在待入场计划之间 | `execution/plan_line.replacement` 只比较名单前 N 只与待入场计划的名次；已买入的不占名额，再次上榜只标「已持有」 |
| 持仓每天只被单独复查 | `save_holding_review` 的结论是成立 / 不成立 / 无法判断，不和候选比较 |
| 系统允许满仓 | `WorkbenchConfig.total_cap = 1.0`；示例配置同值，本机 `config/local.json` 没有设这个键 |
| 上限按总资产算，不看现金，也没有现金下限 | `execution/plan_levels.size` 的 `total` 一项 =（总资产 × `total_cap` − 持仓总市值）÷ 入场上沿 |
| 仓位满时计划照样保存，股数为 0 | `toolsurface/planning.save_plan` 把 `no_room` 记为警告后照常写入 |
| 待入场计划之间不互相占额度 | `_exposure` 只数持仓市值；三份待入场计划各按同一份剩余额度算股数 |
| 卖出指令只有两种来源，且只能卖整份 | `v3_plans.sell_instruction` 的取值只有 `max_hold`、`thesis_broken`；止损触及另记 |
| A 和 B 没有共同的比较尺度 | 名次只对当天筛出的股票算（`facts/ranking`）；其中相对强度（`screen_rs`）与行业档位对任何有日线的股票都算得出，形态档位只对当天触发的股票有意义 |

结论：系统一份一份地看计划，账户只在算股数时出现一次。本版让账户成为一道明确的线：线以内照旧，线以外先回答「值不值得拿一只持仓去换」。

## 2. 目标、非目标、反目标

**目标**

1. **总仓位上限 60%**（用户决定）。持仓总市值不超过总资产的 60%；这条线同时是换仓比较的触发线。
2. **钱够直接买，不够才比较**（用户决定）。按计划买入 B 不会越过上限时，一切照旧，和持仓无关。
3. **换仓结论三选一**（用户决定）：继续持有 / 半仓换 / 全仓换。由 agent 综合判断（用户决定），在全部可比的持仓里最多挑一只 A（用户选定方案一）。
4. **刚买入的持仓也参与比较**（用户决定）。出发点是「当时可能看错了」。
5. **不让换仓变频繁**（用户决定目标；三道闸是我的提议，用户同意其中的频率）：缺省继续持有；每 5 个交易日最多一次（用户决定）；换仓的账摆在结论旁边。
6. **agent 不碰数字**（沿用 v3.1）。卖多少股 A、买多少股 B 全部由宿主算。
7. **每次结论都留记录并事后对照**（我的提议，用户未反对）。包括「继续持有」。复盘里能看到换了之后与不换相比如何。
8. **系统支持卖出一部分**（半仓换的前提，我的判断）。剩余持仓的止损单数量跟着提示修改。

**非目标**

- 每天对整个账户给出目标仓位（§4 方案三）。
- 上限随大盘状态浮动；调整每笔风险 1% 与单只上限 25%。
- 没有候选 B 时主动提示减仓；仓位高于上限时要求卖出。
- 行业集中度限制。
- 再次上榜的待入场计划因额度变化而触发比较（§5.3）。
- 分批止盈、加仓计划（沿用 v3.1 的非目标；本版的部分卖出只来自半仓换）。
- 券商接入、自动下单、盘中行情（沿用）。

**反目标**（即使功能都在，出现这些也算失败）

- 换仓结论里出现 agent 给出的股数、价位或金额。
- 仅因仓位高于上限，系统就给出卖出指令。
- 简报会话在冷却期内又给出一次半仓或全仓结论。
- 止损已触及、或已有卖出指令的持仓被拿来比较。
- 一次半仓或全仓结论只写了 B 为什么强，没写 A 哪里没按预期走。
- 一次比较没有留下记录，或记录里没有当时摆出的那笔账。
- 模型不可用的一天，仓位占比和「仓位已到上限」的提示也跟着没有。这两样由宿主算。
- 换仓让任何一只持仓的止损价变低（沿用 v3.1 的「只上不下」）。

## 3. 约束

v3.1 §3、v3.2 §3 的约束全部沿用。另外：

- **只有日线，收盘后跑一次。** 换仓的两笔交易都发生在下一个交易日及之后，系统看不到当中的价格。
- **agent 的判断和选股规则一样未经验证。** 所以本版把「留记录、事后对照」当成目标而不是附带。
- **v3.2.0 仍在观察期**（roadmap 第 6 步）。本版的迁移编号 037，排在 036 之后；上线需要用户单独授权（§14）。
- **只追加的表不许 `UPDATE` / `DELETE`**（沿用守护测试）。换仓记录是只追加的表。
- **说明文件已规定**「不给出也不修改止损价、卖出价和股数」。本版的工具面必须让 agent 在不写任何数字的前提下完成换仓结论。

## 4. 做法比较

三种做法的共同部分：总仓位上限 60%、三道闸、留记录进复盘、支持部分卖出。区别在于拿哪只 A 来比、由谁决定。

| 方案 | 内容 | 结论 |
|---|---|---|
| **一** | **宿主把全部可比的持仓列成一张表，agent 最多挑一只 A，给出三选一** | **用户选定**。符合「交给 agent 综合判断」；agent 能看到持仓的全貌（例如已在移动止损里锁住利润的不该动）。代价是 agent 自由度大、一次读的东西多，靠记录与复盘约束 |
| 二 | 宿主按一条规则（如相对强度最低）先选出最弱的一只 A，agent 只对这一对给三选一 | 未选。和待入场计划的替换一致、容易核对，但「谁最弱」的规则正是现在没有、也没验证过的那把尺子；选错了 A，后面的判断再好也没用 |
| 三 | 每天对整个账户做一次组合复查，agent 给出每只股票该占多少 | 未选。等于让 agent 决定股数，和「agent 不碰数字」冲突；每天都可能产生调整，和「不频繁换仓」相反；工作量是前两种的几倍。等换仓记录证明 agent 的判断靠得住再考虑 |

**触发线怎么定**

| 做法 | 结论 |
|---|---|
| 买满了（上限 100%）才比较 | 未选。用户认为满仓危险 |
| **总仓位上限降到 60%，越线才比较** | **用户决定**。上限与换仓是同一条线的两面 |
| 另设一条「至少留多少现金」 | 未选。不融资时现金 = 总资产 − 持仓市值，和仓位上限是同一个数，不必有两个配置 |

**怎么防频繁换仓**（我的提议，频率为用户决定）

| 做法 | 结论 |
|---|---|
| 给持仓设最短持有期，期内不参与比较 | 未选。用户要求刚买的也比 |
| **缺省继续持有 + 每 5 个交易日最多一次 + 把账摆出来** | **选定** |

## 5. 仓位上限

### 5.1 口径

- **仓位占比** = 持仓总市值 ÷ 总资产。市值按交易日 S 的最新收盘；总资产沿用 v3.1 §8.3 的「仓位用的本金」。
- **上限**：`workbench.total_cap` 的默认值由 1.0 改为 0.6。股数算法不变（`plan_levels.size` 三项取最小），只是 `total` 一项更早起作用。
- **剩余额度** = 总资产 × 上限 − 持仓总市值，小于 0 记 0。
- 待入场计划不占额度（现有行为，不改）。
- 没有任何资金记录时照旧不算股数，也不做换仓比较，写「未提供账户资金」。

### 5.2 「钱不够」的判定（我的判断）

对一只通过二次确认的候选 B，宿主用现有算法算两个股数：

- **不受总仓位限制的股数** = min(风险一项, 单只一项)。
- **额度内的股数** = 现有三项取最小的结果。

额度内的股数不到前者的一半（配置项，缺省 0.5）时，判为「钱不够」，进入 §6 的换仓比较。否则照旧出计划，股数取额度内的股数（现有的 `capped` 状态）。

理由：上限只让股数少了一点时，不值得为此发起一次换仓。

**用哪套价位判**（审阅记录 R1）：判定一律用宿主的规则价位（`compute_plan_levels` 那一套），在生成待办时算出，当天以待办为准。待办判为「钱够」的候选，agent 之后自报价位保存计划时不重新判定，股数照常取额度内的股数；算出 0 股时拒绝保存并写明「仓位已到上限」，不留 0 股的计划。

### 5.3 越线之后

- **仓位已经高于上限**（例如上线时已有持仓超过 60%，或持仓上涨）：系统不给任何卖出指令。剩余额度为 0，之后每只通过确认的候选都按「钱不够」处理。账户一节如实显示占比。
- **买入后越线**：记成交时，如果这笔买入之后仓位占比高于上限，照记，并记一行偏差「买入后仓位占比 X%，高于上限 60%」。复盘多一个偏差标签「买入后超出仓位上限」（§9）。占比按记成交那一刻的账户视图算：这笔买入按成交价，其他持仓按当时的最新收盘，总资产按当时的账本；算出的数随偏差记录保存，复盘读这条记录，不重算（审阅记录 R9）。
- **再次上榜的待入场计划**：延续时股数按当天额度重算（现有行为）。算出 0 股时计划照常延续，卡片写「仓位已到上限」；本版不为它发起换仓比较（非目标）。

## 6. 换仓比较

### 6.1 什么时候做

同时满足才做，由宿主判定并写进当天待办；agent 不自己决定：

1. B 当天在待办里（新的二次确认，或简报会话里研究复看得出「可以出计划」），并且 agent 对它的结论是「确认」。否决与无法判断不比较。
2. B 按 §5.2 判为「钱不够」。
3. 至少有一只可比的持仓（§6.2）。
4. 当天的简报会话还没有留下换仓记录（每个交易日最多一次）。「做过」以存下一行换仓记录为准，三种结论都算；B 被否决或无法判断没有产生记录，不算，下一只满足条件的候选仍可以比较。对话里的比较不占这一次（§7.3）。
5. 不在冷却期：最近 5 个交易日（含当天，配置项）内没有已生效的半仓或全仓结论，简报与对话的都算。「继续持有」不进入冷却；之后被撤回的换仓指令仍然算数；没做完的结论（§6.5）不算。

条件 2 成立而 3、4、5 任一不成立时：不比较，B 不出计划，名单里写明原因（「仓位已到上限，没有可比的持仓」/「仓位已到上限，当天已比较过一次」/「仓位已到上限，冷却期内（上次换仓 MM-DD）」）。

这样的候选留在待办里，标明不比较及原因，直接算作已完成，agent 不必为它做二次确认（我的判断，为节省会话预算；审阅记录 R3）。待办每次读取时现算：当天第一次比较存下之后，后面「钱不够」的候选随即变成这种状态；它如果此前已经有了确认结论，结论保留，名单里同时写结论与不比较的原因。

名额规则（v3.1 §6.4）与本节相互独立，先过名额，再看额度：没有空名额也不满足替换条件的候选，本来就不做确认。

### 6.2 哪些持仓可比

已买入的计划，且当天：

- 止损没有触及；
- 没有任何卖出指令（持有到期、论点失效、尚未执行完的换仓）；
- 有当天的日线（不是「缺日线，无法检查」）；
- 当天的持仓复查结论不是「不成立」（那只本来就要卖）。

补录的持仓可比（用户已有的仓位同样占额度）。持有天数不设下限（用户决定）。半仓换之后剩下的那一半是普通持仓，冷却期过后可以再次被比较。

**什么时候算这份清单**（审阅记录 R10）：生成待办时当天的持仓复查可能还没做，条件 3 先按前三条判；读比较表和保存结论时再按四条现算。被选为 A 的持仓必须已有当天的复查结论（成立或无法判断）。保存时清单已经空了，这一项改记「仓位已到上限，没有可比的持仓」并算作完成，B 不出计划。

### 6.3 摆给 agent 的那张表（宿主算）

**每只可比的持仓**

- 股数、平均成本、最新收盘、市值、占总资产的比例。
- 浮动盈亏（金额、百分比）；相当于计划风险的几倍（补录的写「补录，不计」）。
- 当前止损、离止损的距离、是否已进入移动止损。
- 已持有交易日数、离最长持有还剩几天。
- 相对强度（与名单同一个公式）、行业与行业档位。
- 当天的持仓复查结论与理由。
- 半仓、全仓各自的账：卖出股数、按最新收盘估的卖出所得、会实现的盈亏。

**候选 B**

- 名次、规则理由、相对强度、行业档位、形态档位。
- 宿主算的价位、计划风险金额。
- 对每只可比持仓：半仓换、全仓换之后 B 各能买多少股（§6.5）。

**成本与频率**

- 两笔交易的手续费估计：取最近 20 笔未作废成交的费用中位数 × 2；没有成交记录时写「没有费用记录，按 0 计」。
- 上一次半仓或全仓结论的日期，以及最近 20 个交易日内的次数。

这张表原样存进换仓记录（§6.6），之后复盘用的就是当时这一份。

### 6.4 结论（agent）

三选一：

| 结论 | 含义 | agent 必须给出 |
|---|---|---|
| 继续持有 | 不动持仓，B 不出计划 | 理由、反证、引用的工具调用；可以指出「最接近被换的是哪只」，也可以不指 |
| 半仓换 | 卖出 A 的一半，买入 B | 选定的 A、B 为什么更强、**A 哪里没按预期走**、反证、对那笔账的回应、引用的工具调用 |
| 全仓换 | 卖出全部 A，买入 B | 同上 |

- **缺省是继续持有。** 只有「B 更强」不够；agent 指不出 A 本身的问题，就只能选继续持有。宿主校验「A 哪里没按预期走」一栏非空，且引用里至少有一次对 A 的读取。「对 A 的读取」指本会话里以 A 为参数的单只股票读取（日线、指标、资讯、申报、财报日、基本面任一）；只读过比较表不算（审阅记录 R6）。
- 半仓与全仓的分界由 agent 综合判断（用户决定），本版不给规则。
- agent 最多选一只 A；不能把两只持仓各换一部分。
- A 只有 1 股时，宿主拒绝「半仓换」。
- 结论不带任何数字字段；工具的入参里没有股数、价位、金额。

### 6.5 宿主把结论变成操作

- **继续持有**：留记录；B 的保存计划被拒绝，原因「仓位已到上限，比较后继续持有」。
- **半仓换**：卖出股数 = A 的持仓股数 ÷ 2，向下取整。**全仓换**：卖出全部。
- **B 的股数**：沿用现有算法，其中持仓总市值减去「卖出股数 × A 的最新收盘」。也就是假设 A 已按最新收盘卖出。算出来不到 1 股时拒绝这次换仓结论并说明原因。
- **A 得到一条换仓卖出指令**：「下次开盘卖出 N 股，原因：换仓至 B」。它带数量，是本版新增的第三种卖出指令。
- **B 的计划照常保存为待入场**，有效期、名额规则都不变；计划上注明「资金来自换仓：A，N 股」。
- **换仓的 B 只用宿主的规则价位**（审阅记录 R1）：这份计划不接受 agent 自报价位，之后修订也不能改价位（论点、作废条件、最长持有可以改）。这样判定、比较表里的股数、最终计划的股数是同一个口径。
- **B 之后延续或修订时的股数**（审阅记录 R2）：A 的换仓指令还在、没卖完时，仍按「指令里还没卖的股数已按最新收盘卖出」算额度；指令已执行完、被撤回或被取代之后，回到普通口径。这个口径只用于这一份 B 的计划，别的候选算额度时不扣。
- **保存结论之前先过一遍保存计划的拒绝条件**（审阅记录 R4）：名额与替换、财报进入有效期、该股票已有有效计划等。B 的计划注定存不成时，半仓或全仓的结论直接被拒绝并说明原因。
- **A 的指令与 B 的计划同时成立**：A 的指令只在 B 的计划存下的那一刻落库。不允许出现 A 有指令而 B 没计划的状态。
- **没做完的结论**：半仓或全仓的记录已存、而到当天会话结束 B 的计划仍没存下（预算耗尽等）。这一行记为「未完成」：A 没有指令，不进冷却，复盘里单列为未完成、不算对照；第二天不补做，B 再次上榜时重新走一遍。同一天内的重试照常从没做完的那一步接着做（沿用 v3.1 §9.4）。实施者可以把结论与 B 的计划合进同一次调用来消除这种状态。

**操作顺序与没买到的情况**（我的判断）：先卖 A，再按计划买 B。B 的买入要等价格进入入场区间，可能买不到；那时 A 已经卖了，钱留作现金。系统如实记录，不补救。理由：换仓的前提之一是 A 没按预期走，卖出 A 本身站得住；而先买 B 再卖 A 会让仓位暂时越过上限。

### 6.6 换仓指令之后

- **优先级**：止损触及、持有到期、论点失效都高于换仓指令。A 之后出现其中任何一种，按那一种处理（卖出全部），换仓指令被取代并记一行。
- **取代就是覆盖**（审阅记录 R7）：A 的卖出指令改成新的原因，换仓的数量与对方股票不再留在计划上，只留在换仓记录和那一行变化里。现有代码里持有到期与论点失效都只在「没有卖出指令」时才触发（`plan_line.holding_check`、`save_holding_review`），本版要改成「没有卖出指令，或只有换仓指令」时触发。B 的计划不受影响。
- **离场原因取最后一次卖出时的原因**（审阅记录 R8）：只有在换仓指令之下卖完的才记「换仓」。半仓换卖掉一半、剩下一半后来止损的，离场原因记止损；换仓的那一半看换仓记录与时间线。平仓盈亏照旧把所有批次合在一起算。
- **撤回**：B 的计划没买就结束（过期、作废、被替换、取消），而 A 还没按指令卖完 → 宿主撤回换仓指令，记一行「换仓指令撤回：B 的计划已过期」。这是换仓指令与另两种卖出指令的不同之处：另两种给出后不会自行撤回。
- **用户可以撤回**：对话或页面上「撤回换仓指令」，先复述、确认后写入。换仓不是纪律，不执行不算偏差（§9）。
- **执行完**：指令给出之后，A 的卖出成交累计达到指令的股数，指令消失。卖完则计划变为已平仓，离场原因记「换仓」。
- **部分卖出之后的止损单**（适用于任何一次没卖完的卖出，不只换仓）：剩余持仓的止损价不变，「今日操作」显示「A 止损单数量需改为 N 股」，直到用户再次确认挂单。
- **止损纪律不变**：换仓不改变 A 的止损价；B 买入后照常「买入即挂单」。

### 6.7 记录

每次比较一行，只追加：交易日、来源（简报 / 对话）、B、结论、选定的 A（继续持有时可为空）、理由、A 的问题、反证、对那笔账的回应、引用的工具调用、§6.3 的那张表、宿主算出的卖出股数与 B 的股数。同一个交易日的简报会话只能有一行。

A 与 B 的计划各记一行变化（「换仓指令：卖出 N 股，换至 B」「新建：资金来自换仓 A」），时间线照常能看到。

## 7. 简报会话与对话

### 7.1 待办

- 持仓复查排在最前（现有顺序），保证做比较时当天的复查结论已经有了。
- 候选的待办项多一个由宿主给出的标记：是否需要换仓比较；不比较时的原因。
- agent 的步骤：先照常做 B 的二次确认并保存结论 → 结论是确认且待办标明需要比较时，读 §6.3 的表 → 保存换仓结论 → 半仓或全仓时照常保存 B 的计划（股数由宿主按 §6.5 算）。
- **完成判定**（v3.1 §9.4 追加）：需要比较的那一项，以「B 被否决或无法判断」「换仓结论为继续持有」「换仓结论为半仓或全仓且 B 的计划已保存」三者之一为完成。
- 没完成时最终简报写「换仓比较未完成」和原因；A 不产生任何指令。

### 7.2 操作手册与说明文件

操作手册加一节「换仓比较」，写明：缺省继续持有；两个条件都要成立；必须回应那笔账；最多选一只；不写数字。说明文件的硬性规定加一条：换仓结论只能通过换仓工具给出，不在一句话总结或持仓复查里暗示卖出。措辞留给实施者。

### 7.3 对话（我的判断）

- 用户可以问「要不要把 A 换成 B」。agent 用同一张表、同一个工具给结论；写入前复述、用户确认后才写（沿用对话写入的约定）。
- 对话里仍要求 B「钱不够」且有当天的确认结论（名单内股票或「可以出计划」的研究）。钱够时回答「额度足够，直接出计划即可」。
- 对话里由用户发起的比较不受「每天一次」与冷却期限制（与 v3.1 §6.4 对话里的替换同一个道理：这是用户自己的决定），但工具返回里带「最近 5 个交易日已换仓 N 次」，agent 必须在复述里说出来；结论照常计入冷却。
- 对话里的比较不占简报会话的「每天一次」：§6.1 条件 4 只数来源为简报的记录。对话用哪个交易日沿用 v3.1 §9.1（当时最新一份成功运行记录的交易日）（审阅记录 R5）。
- 用户可以在对话里指定 A；agent 仍要给出理由，也可以给「继续持有」。

## 9. 复盘

全部由宿主从记录现算，不用模型；口径未经验证，页面上照例写明。

**每次比较一行**

- 交易日、B、A、结论、理由摘要。
- 执行情况（只对半仓与全仓）：A 是否按指令卖出、卖了多少、哪天；B 是否买入；指令是否被撤回或被取代。
- **之后的对照**（我的判断）：从结论的下一个交易日开盘起，到第 5、10、20 个交易日收盘，A 与 B 各自的涨跌幅，以及 B 减 A 的差。日线不够的写「进行中」。继续持有的结论同样算这一项，用来看「没换是不是对的」；继续持有而没指明 A 时不算。

**汇总**

- 三种结论各几次；半仓与全仓里执行了几次；手续费估计合计。
- 半仓与全仓：20 个交易日后 B 跑赢 A 的次数占比、差值的平均。继续持有：同样两个数。
- 样本数低于 `v3.retro_min_sample`（现为 10）时只给次数，写「样本不足」，不给占比与平均（沿用 v3.2 §5.5）。

**与现有复盘的衔接**

- 平仓结果的离场原因多一种「换仓」。
- 偏差标签多一个「买入后超出仓位上限」（§5.3）。
- 「卖出指令后晚卖」不适用于换仓指令：不执行换仓不算偏差。
- 周报加一段：本周的换仓结论各一行。

## 15. 验收

| # | 标准 |
|---|---|
| C1 | 仓位占比、剩余额度与手算一致；上限 0.6 时，同一组输入下股数比上限 1.0 时少或相等 |
| C2 | 钱够：额度内的股数不低于不受限股数的一半时，照常出计划，不产生换仓记录 |
| C3 | 钱不够且条件齐备：待办里出现比较项；agent 存「继续持有」后 B 的保存计划被拒绝并写明原因，A 没有任何指令 |
| C4 | 半仓换：A 的指令股数 = 持仓 ÷ 2 向下取整；B 的股数与「假设 A 已按最新收盘卖出 N 股」的手算一致；A 只有 1 股时半仓被拒绝 |
| C5 | 全仓换：A 的指令为全部股数；记下卖完的成交后 A 变为已平仓，离场原因「换仓」 |
| C6 | 保存换仓结论的校验各有一个被拒绝的测试：A 不在可比清单里（止损已触及、已有卖出指令、缺日线、当天复查「不成立」、当天还没有复查结论各一个）、半仓或全仓缺「A 哪里没按预期走」、引用里只有比较表而没有以 A 为参数的单只股票读取、入参带数字字段、B 当天没有确认结论、B 钱够、B 的计划注定存不成（没有名额、财报进入有效期各一个） |
| C7 | 冷却：半仓或全仓结论之后的 5 个交易日内，简报待办里的「钱不够」候选标为不比较并算作完成，名单写明原因与上次日期；「继续持有」不触发冷却；同一交易日第一次比较存下之后，第二只「钱不够」的候选不比较；第一只被否决时第二只仍可比较；对话里的「继续持有」不占简报当天的一次 |
| C8 | 撤回：B 的计划过期、作废、被替换、取消四种结束，A 未卖完的换仓指令都被撤回并留记录；用户在对话与页面撤回各一个测试 |
| C9 | 取代：A 有换仓指令后止损触及、持有到期、论点失效，各自按原规则处理并留一行「换仓指令被取代」 |
| C10 | 部分卖出后「今日操作」出现「止损单数量需改为 N 股」，再次确认后消失；A 的止损价不变 |
| C11 | 买入后仓位占比高于上限：成交照记，留偏差记录，复盘出现对应标签 |
| C12 | 仓位高于上限而没有候选的一天：没有任何卖出指令 |
| C13 | 模型不可用的一天：草稿里有仓位占比、剩余额度，以及对「钱不够」候选的「换仓比较未做」 |
| C14 | 会话在保存换仓结论之后、保存 B 的计划之前被杀：当天重试只补做剩下的一步；始终没补上的，记录为「未完成」，A 没有指令，不进冷却，第二天不补做 |
| C20 | 换仓的 B：自报价位的保存与修订价位被拒绝；A 未卖完时延续，B 的股数仍按扣掉 A 待卖股数算；A 卖完或指令撤回后延续，按普通口径算 |
| C21 | 待办判为「钱够」的候选用自报价位保存而算出 0 股：保存被拒绝并写明「仓位已到上限」 |
| C22 | 半仓换卖出一半后，剩余持仓后来止损触及并卖完：离场原因记止损，盈亏合并两批计算 |

## 17. 审阅记录

2026-11-11 写成后，交给一名独立审阅者以「拿到文档就要排实施计划、不能再问设计者」的角度对着现有代码读了一遍。提出十个问题，都属于设计者可以定的口径，没有需要用户另行回答的；处理如下，均为我的判断。

| # | 问题 | 处理 |
|---|---|---|
| R1 | 「钱不够」的判定在保存计划之前做，而 agent 保存时可以自报价位，两处算出的股数可能对不上 | §5.2：判定用宿主规则价位，当天以待办为准；§6.5：换仓的 B 只用规则价位；验收 C20、C21 |
| R2 | B 的股数按「A 已卖出」算，延续时按当天额度重算会缩水 | §6.5：A 的指令未执行完时沿用换仓口径，之后回到普通口径；验收 C20 |
| R3 | 「每天最多一次」怎么体现在现算的待办与完成判定上 | §6.1：以存下一行记录为准；不比较的候选留在待办里并算作完成；验收 C7 |
| R4 | 半仓或全仓结论已存而 B 的计划始终没存成 | §6.5：保存结论前先过保存计划的拒绝条件；剩下的情况记「未完成」，不进冷却，第二天不补做；验收 C6、C14 |
| R5 | 对话里的比较会不会占掉简报当天的一次；对话用哪个交易日 | §6.1 条件 4、§7.3：只数简报来源的记录；交易日沿用 v3.1 §9.1 |
| R6 | 「引用里至少有一次对 A 的读取」读比较表算不算 | §6.4：必须是以 A 为参数的单只股票读取；验收 C6 |
| R7 | 现有代码里持有到期与论点失效只在没有卖出指令时触发，A 有换仓指令后「取代」不会自然发生 | §6.6：取代就是覆盖，触发条件放宽到「只有换仓指令」；验收 C9 |
| R8 | 半仓换之后剩余持仓的离场原因与能否再次被比较 | §6.6：离场原因取最后一次卖出时的原因；§6.2：冷却期后可再比较；验收 C22 |
| R9 | 「买入后超出仓位上限」按什么价格与时点算 | §5.3：按记成交那一刻的账户视图，算出的数随偏差记录保存 |
| R10 | 生成待办时当天的持仓复查还没做，「可比」怎么判 | §6.2：待办先按前三条判，读表与保存时现算；选定的 A 必须已有当天的复查结论 |

**2026-11-11 写实施 plan 时的两处澄清**（只增不改，冲突时以这里为准）：

- **冷却的口径**以 §6.1 条件 5 为准：半仓或全仓结论所在的交易日记为 R，从 R 到当天（两端都算）不超过 5 个交易日时在冷却期内。也就是 R 之后的 4 个交易日不比较，第 5 个交易日可以比较（周一换仓，下周一可以再比）。验收 C7 里「之后的 5 个交易日内」按这个口径理解。
- **「没做完的结论」不会出现**：实施 plan 采用 §6.5 末尾允许的做法，把半仓或全仓的结论、B 的计划、A 的指令放进同一次调用、同一个事务。验收 C14 相应改为：这次调用中途失败时三者都不落库，重试重新做这一步。
