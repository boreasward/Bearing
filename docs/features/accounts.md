# 账户与模拟交易

真实账户把已录入的成交和出入金算成每日账本权益；模拟账户按同一批计划分别执行「照计划执行」和「Agent 自管」，保留下单、校验、成交与持仓证据。模拟订单只在本地账本结算，不连接券商。设计见 [v2.11 账户与模拟交易](../specs/2026-10-31-v2.11-accounts-and-paper-trading-design.md)。

## 账户与开账

系统只有一个真实账户。开账填写期初现金、开账日及可选的已有持仓；期初现金必须大于零，已有持仓按开账日纽约 16:00 的期初买入保存，标记 `opening_position`，不重复扣减现金，也不关联计划。已有成交或出入金时，开账日不能晚于最早一笔有效记录。真实账户只允许开账一次，不能关闭。

开账后新增成交的纽约日期、出入金日期必须不早于开账日，避免用开账前的记录再次改变期初值；资金快照仍可录入更早日期。写入与开账共用账户锁，先核对请求幂等性，再检查日期边界，因此已有请求的原样重试仍返回原记录。开账检查在拿到锁后读取当前全部有效记录，包含等待锁期间已提交的补录；请求时间仍用于审计与输出，不作为这一写入约束的过滤截止。未开账或尚未迁移到 030 时，旧成交与出入金录入行为保留。

模拟账户可新建多个，策略为 `follow_plans`（照计划执行）或 `agent_managed`（Agent 自管）。默认期初现金 100000，开账日为下一个交易日（因此建账当天运行 `daily` 不会为它产生决策，首笔挂单在开户日收盘后下、再下一个交易日成交）；参数继承工作台仓位设置，并有零手续费、最多八个持仓及对账容差的默认值。`request_id` 相同且内容相同的创建请求返回原账户，内容不同返回冲突；名称不能重复。

参数修改必须写理由和 `request_id`，追加审计记录，下一交易日起用于决策；不会重算已经完成的模拟结算。关闭模拟账户也要写理由，并在同一事务里把该账户全部在挂订单撤成 `cancelled`（原因 `account_closed`，结算日为关闭时的纽约日期）；之后仅保留历史读取，不再结算、估值或决策。账户接口只返回公开参数，不暴露审计中用于幂等判断的元数据。

## 每日结算与决策

每日图 `daily-2` 的第九个节点 `accounts` 位于 `review` 之后、`push` 之前，阶段口径为 `stages-5`（十一节点）。休市日跳过。节点按以下顺序处理：

1. 结算全部已开账、活跃的模拟账户，从各自 `settled_through` 后第一个交易日逐日补到本次交易日；每个账户独立事务，某个账户失败不会阻止其他账户。
2. 追加真实账户的账本权益。未开账时不生成；每次重算至少最近五个交易日，停机更久则补齐中间日期，用现在已经知道的补录与作废信息重算，变化才追加新版本。
3. 写模拟账户当日持仓状态，读取该账户的成交与冻结入场计划，不采用真实账户的全局链修订。
4. 对全部模拟账户撤销仍在挂的过时买单，再执行「照计划执行」账户，最后按创建顺序执行「Agent 自管」账户；每个账户每个交易日只保存一次决策。

同日重跑复用已有决策，不重复调用模型、下单、结算或写持仓状态。账户锁覆盖检查和写入，成交使用由账户、交易日与成交顺序确定的请求标识。节点失败会留下账户级证据，后续推送与复盘仍执行。运行详情列出每个账户的成交、作废、过期、撤单、退出数量，以及权益、持仓和决策状态。

账户节点开始时单独冻结一次截止时间，交易日仍沿用整次运行的交易日。这样本次上游刚生成的计划与复查可以参与当日决策，而晚于账户截止时间的版本仍不可见。节点详情与决策证据都记录这个时间；续跑时已有决策保留原截止时间，尚未解决的账户使用新一次节点开始时间。整次运行摘要的截止时间仍表示运行起点。

两种模拟策略都由宿主检查待成交买单：节点截止时间前已有新入场版本时记 `superseded_by_revision`，链已结束或下个交易日已不可入场时记 `chain_ended`。撤单在当日结算之后、模型之前独立提交；模型关闭、不可用或输出无效也会执行。当天已经成交的旧单及其冻结持仓保留，真实链变化不会自动退出模拟持仓。节点统计本次实际撤单数量，决策详情另记 `detail.host_cancellations`，不改写模型原始输出；同日已有决策时直接复用，不再次协调。

「照计划执行」只选下一个交易日可买的链头计划，依仓位、现金和持仓数量上限依次分配；先释放有效撤单占用，再校验买单，卖单的次日收入不预支。已经成交或开盘作废的链永久消费；过期、撤单只消费对应版本；宿主拒绝的订单不消耗版本，次日可改正（例如缩到股数上限内）后重下，Agent 能看到前一日的拒绝原因；Agent 自管账户是否买入新版仍由 Agent 决定。一个账户的同一标的最多有一份未平持仓，同标的其他链不能叠加买入。

「Agent 自管」的输入和限制见 [Agent 轨道 · 账户决策](agent-track.md#账户决策)。其 600 秒预算独立于计划 Agent 与复查的 1500 秒窗口；模型不可用、额度用尽或 token 达限只跳过决策，已完成的结算保留。

## 模拟成交规则

订单结果原因按枚举落库并有中文：撤单 / 过期原因 `superseded_by_revision`、`chain_ended`、`agent_cancel`（Agent 撤单；原文保留在撤单行的理由里）、`validity_expired`、`account_closed`，作废原因沿用 `entry-1` 的 `gap_below_stop`、`gap_above_zone`、`gap_below_zone`，计划链消耗原因 `entry_voided`、`exited`（目前不在页面展示，词表预留）；中文表在 `paper_fill.py` 与 `lib/accounts.ts` 各一份，由跨语言测试守护。T1 卖半与 Agent 卖一半取成交日股数的一半向下取整（补结算时已知后来的拆股，也按成交日股数取整），结果为 0 时不产生卖出成交（T1 仍把状态推进到 T1 之后的移动止损）。

模拟订单从下一个交易日起按日线结算，复用 `entry-1` 入场判断与持仓止损规则：区间内、跳空回落限价、低开回升触发分别记下成交情形；开盘越过止损、有效期结束等分别留下作废或过期记录。已有持仓先执行 Agent 的开盘卖单，再对剩余持仓执行宿主止损、T1 和时间退出规则；Agent 卖出一半不取消余仓的宿主保护，T1 卖出一半后也保留余仓止损。订单只允许从待成交变成终态。

持仓使用买入时冻结的计划，后来的全局链修订不会修改它。拆股时将冻结状态的价位统一到当前股数口径，成交记录恢复到成交日口径，由 FIFO 账本应用拆股一次。持仓状态在每日权益证据里保存，跨日、停机补算和缺行情后继续运行都沿用。持仓指令和剩余期限取自结算后的状态：T1 已卖半就继续管理余仓，时间退出到期则等待下一根有效日线的开盘；手续费计入账本成本，但不会抬高宿主按成交价计算的保护价，缺行情日也不会增加已观察的持有天数。

缺少当天日线时不猜测成交，待成交订单和持仓状态保留，并记录行情缺口。估值可沿用最近收盘，但 `detail.stale` 和 `bars_missing` 会标出；完全无价格时该持仓估值为零并标记不完整，不能当成完整权益。模拟成交无滑点，默认手续费为零，不模拟盘口、成交量约束或盘中价格路径。

## 权益、对账与对比

账本权益 = 期初现金 + 累计净出入金 − 普通买入支出 + 卖出收入 − 手续费 + 未平持仓市值。期初持仓不会再次扣现金。权益表只追加，同一日期读取最新计算版本；同样输入的重复计算不新增行。真实账户补录会追加历史日期的新计算结果，不改旧成交、资金快照或已冻结的周月复盘。

券商资金快照继续独立录入，用于与同日账本权益只读对账；超出容差显示待核对，不自动修改任何一边。真实账户未开账时显示暂无账本权益，旧快照仍可用于仓位与月收益。

账户对比使用同一个截止时间，按固定顺序显示累计收益、本月收益、最大回撤、平仓数与胜率、平均 R、纪律四项、未执行计划、持仓与待成交数。纪律和实际轨道复用既有 `discipline-2` / `tracks-2` 算法，但成交与持仓按账户隔离；平均 R 少于五个已平样本时为空并说明原因，不把未知当零。SPY 曲线与账户权益日期对齐。全局计划链、每日推送、复盘卡及周月复盘继续默认读取真实账户。

自开户收益率用修正 Dietz：起点为开账首个交易日（`opening_session`）权益行扣除累计净出入金，因此开账带入的实物持仓计入起点而不被当成收益；首个交易日缺行、或该行估值不完整（`bars_missing` / `stale`）、起点非正时为空。收益区间自开户首个交易日收盘起算，开户当天的盘中盈亏不计入。

页面本月收益以「上月最后交易日 → 截止交易日」为固定区间，使用两个精确日期的完整账本权益并扣除区间净出入金；缺少账本端点或端点估值不完整时，只能回退到相同两个日期的有效资金快照，并注明 `snapshot`。仍缺端点则显示无值及原因，不使用临近日期或缺价时的零估值代替。SPY 本月收益要求同一对交易日收盘。已冻结月报继续使用 `monthly-5` 的完整月末定义，页面本月至今口径不会改写历史月报。

## 页面

账户入口为 `#account`，默认显示真实账户；`#account/<id>` 显示指定账户，`#account/<id>/<tab>` 打开对应页签。账户切换条显示名称、策略与参数摘要，并提供新建模拟账户入口。真实账户未开账时，概览顶部引导填写期初现金、开账日与已有持仓，经过两次确认后写入；成交与持仓历史仍可查看，原有资金快照、出入金读取与录入继续保留，成交录入按后端表单权限提供。

- **概览**：显示六项指标、归一化权益曲线、SPY 与其他账户叠加。真实账户提供券商快照对账、成交录入、出入金与资金快照录入；模拟账户显示当日完整决策订单。
- **持仓**：显示当前持仓、成本、现价、浮盈、R、止损与 T1 距离、持有期限及冻结计划链，并列出已平仓批次。窄屏使用带字段名称的卡片。
- **成交**：显示本账户成交、记录来源、成交情形与退出原因；真实账户作废成交需要填写理由并确认。
- **Agent 决策**：按日展开七段证据、决定原文、理由、宿主检查、成交结果、holds 与总结；跳过日显示原因。照计划执行账户的页签名为「执行记录」。
- **对比**：在 `#account/compare` 叠加活跃账户与 SPY 曲线，并按后端返回顺序显示指标。账户曲线仅在开账当日或之后的首个交易日具有完整、可用权益时归一到 100；首个交易日不同，收益区间不同。概览保留实际开账日期，并显示后端返回的首个交易日；周末或节假日开账不会改写开账日期，也不会任取首条历史代替缺失的首个交易日。SPY 按日期合并、去重所有已读取账户历史中的有效收盘，不依赖首个账户是否已开账。平均 R 样本不足五笔时显示原因，不排序或标注优胜账户。

统计块显示口径版本与截止时间，金额保留后端字符串。概览、持仓、对比表及历史叠加曲线均标出受影响账户、日期与缺失或沿用旧收盘的原因；无可用收盘价时不把零市值、零浮盈当成完整结果。估值不完整的历史日期在曲线中留空且不连接缺口；首个交易日权益缺失、非正数或不完整时不绘制该账户归一化曲线，并说明原因。今日盈亏仅在当日与上一权益行均已核验完整时展示后端原值；历史仍在读取、读取失败、无法确认上一行或首个交易日没有上一行时留空，并说明日期与原因。依赖不完整账本估值的收益率与最大回撤暂不展示。模拟账户与对比页持续显示「模拟成交，无滑点」。参数修改于下一交易日生效；关闭模拟账户后仅能读取历史。切换账户会关闭当前账户的操作弹窗；已发出的写入仍按提交时的目标执行，旧请求返回后不会覆盖新账户的弹窗、表单或错误状态。

复盘页移除「交易与持仓」「资金」页签；旧地址 `#review/trades` 重定向到真实账户成交页，`#review/account` 重定向到真实账户概览。「纪律」「轨道对比」使用 `?account=` 保存账户选择，默认真实账户，选择只影响这两个页签。

## 接口与命令行

金额与股数统一返回十进制字符串。账户对象统一保留原 `opened_on`，并返回由现有交易日历确定的首个交易日 `opening_session`（未开账为 `null`）；允许周末、节假日开户，归一化曲线以该首个交易日为 100。读取接口使用只读事务，不拉取行情或调用模型。

订单 `shares` 保留下单时的预计股数，卖出一半按当时持仓数量除以二保存；`portion` 与 Agent 原始输出保持不变。订单已成交且能关联本账户成交记录时，`filled_quantity` 返回实际成交股数，否则为 `null`；拆股可使实际成交股数与预计股数不同，读取不会改写历史订单或成交。

| 接口 | 内容 |
| --- | --- |
| `GET /api/accounts?include_closed=` | 默认活跃账户；返回公开参数、最新权益、累计收益、最大回撤与开账状态 |
| `POST /api/accounts` | `{request_id,name,strategy,opening_cash,opened_on?,params?}`，返回 `{status,account}` |
| `POST /api/accounts/{id}/opening` | `{request_id,opening_cash,opened_on,opening_positions?}`，返回 `{account,trades}` |
| `POST /api/accounts/{id}/params` | `{request_id,params,reason}`，返回 `{account,change}` |
| `POST /api/accounts/{id}/close` | `{reason}`，返回账户 |
| `GET /api/accounts/{id}` | 账户、权益、当前与已平持仓、待成交、决策摘要、对账与表单权限 |
| `GET /api/accounts/{id}/equity?from=&to=` | 权益行与相同日期的 SPY 收盘 |
| `GET /api/accounts/{id}/trades` | 本账户成交及计划标签 |
| `GET /api/accounts/{id}/orders?status=` | 订单、宿主校验文本与当前成交结果 |
| `GET /api/accounts/{id}/decisions?session=` | 无日期取摘要列表；指定日期取证据、原输出、holds 及订单结果 |
| `GET /api/accounts/compare?from=` | 固定顺序的对比行、账户列、SPY、截止时间与口径版本 |

旧的成交、资金快照、出入金、纪律与轨道读取接口可传 `account_id`，默认真实账户。人工成交与资金写入只允许真实账户：给模拟账户分别返回 `paper_account_is_host_managed`、`flows_only_for_real_account`。作废成交仍只需 `{reason}`，只能作用于真实账户的记录。

开账冲突为 409 `already_opened`；开账日晚于既有记录为 400 `opened_on_after_records`；新成交或出入金早于开账日为 400 `record_before_opened_on`；关闭真实账户为 400 `cannot_close_real_account`。非法 UUID 或日期返回 4xx。未执行迁移 030 时账户接口返回 503 `migration_030_missing`，每日首次运行在开始工作前失败并记录此原因；CLI 与函数续跑也在锁内、调用图或写运行记录之前拒绝执行。旧运行的只读历史及旧成交、资金快照和出入金入口仍保持迁移前兼容。

只读概览命令：

```bash
.venv/bin/python -m investment_assistant.workbench.paper_accounts show
.venv/bin/python -m investment_assistant.workbench.paper_accounts show --account <账户ID或名称> --session 2026-10-30
```

命令按账户显示权益概览、指定交易日的持仓与待成交订单，以及该日决策的总结、订单校验与成交结果、持有理由；未指定日期时使用最近收盘交易日。历史查询按当前已知记录还原指定日期的持仓和待成交状态，决策订单同时显示当前已知的后续成交结果。无持仓、无挂单或当日无决策会明确标出，读取不会触发结算或补决策。

## 验证与限制

在迁移到 030 的一次性数据库里新建两个模拟账户，用固定行情和模型替身执行 `accounts` 节点：检查补齐每个漏跑交易日、每个运行日一条决策、成交与持仓按账户隔离，再重跑同日确认模型调用数、成交数、权益版本数和持仓状态行数不增加。加入缺行情、拆股、开盘作废、模型不可用和单账户失败场景，核对原始证据与运行详情。

`plan_review check` 同时检查实际执行过账户节点的交易日是否缺少已开账账户权益或模拟决策；停机补算的中间交易日只要求结算，不补造当日决策。针对性自动测试位于 `test_workbench_paper_accounts.py`、`test_api_accounts.py`、账户纯函数与迁移测试；这里描述的是本地实现和隔离验证方式，不表示真实库已迁移或服务已部署。

当前不支持同账户同标的的多条并行持仓、负期初现金、模拟账户手工成交或出入金。日线模拟无法还原盘中先后路径，收益不构成实盘执行能力的证据；缺行情和不同开账日期必须连同数值一起阅读。
