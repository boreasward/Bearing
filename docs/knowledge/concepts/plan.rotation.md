## 是什么

计划线管的是一只股票从待入场到离场；换仓比较管的是账户这一层：持仓 A 在、候选 B 通过了二次确认，钱却不够买 B，要不要拿 A 的仓位去换。出发点是「假设我当时看错了 A，现在看到一个更合适的 B」，同时防止为一点点差别频繁换仓、磨损成本。

## 怎么算 / 从哪来

**什么时候比较**（宿主判定、写进当天待办，agent 不自己决定）：

- B 当天的二次确认结论是「确认」；
- B 判为「钱不够」：额度内能买的股数不到不受总仓位限制的股数的一半（见[建议仓位](plan.sizing.md)；钱够就直接出计划，和持仓无关）；
- 至少有一只可比的持仓：已买入、止损没有触及、没有任何卖出指令、有当天日线、当天持仓复查不是「不成立」；刚买入的也可比，补录的也可比；
- 不被三道闸之二、之三挡住。

**三种结论**（agent 综合判断，全部可比持仓里最多挑一只 A）：

| 结论 | 含义 |
| --- | --- |
| 继续持有 | 不动持仓，B 不出计划；这是缺省 |
| 半仓换 | 卖出 A 的一半（向下取整，A 只有 1 股时不行），买入 B |
| 全仓换 | 卖出 A 的全部，买入 B |

**三道闸**：

1. **缺省继续持有**：只有「B 更强」不够。半仓或全仓必须写出 A 哪里没按预期走，引用里要有一次以 A 为参数的单只股票读取，指不出 A 本身的问题就只能继续持有。
2. **频率**：简报会话每个交易日最多一次；最近 5 个交易日（`v3.rotation_cooldown_sessions`）内已有半仓或全仓结论则冷却，期内的「钱不够」候选不比较、名单里写明原因与上次日期；「继续持有」不进冷却。
3. **账摆在结论旁边**：宿主按最近成交的费用中位数估算两笔交易的手续费，连同半仓 / 全仓各自会实现的盈亏一起摆在比较表里，半仓或全仓必须回应这笔账。

agent 不写任何数字：卖出多少股 A、买多少股 B、B 的价位全由宿主算（B 只用规则价位，A 按最新收盘假设已卖出来算额度）。结论、B 的待入场计划、A 的换仓指令在同一个事务里落库，要么都有、要么都没有。

**换仓指令与另两种卖出指令的区别**：

| | 持有到期 / 论点失效 | 换仓 |
| --- | --- | --- |
| 数量 | 卖出全部 | 带数量（半仓或全仓），只卖 N 股 |
| 撤回 | 给出后不自行撤回 | 可撤回：B 的计划没买就结束（过期、作废、被替换、取消）时宿主自动撤回，用户也可以在对话或页面撤回 |
| 优先级 | 高于换仓，会取代换仓指令 | 止损触及、持有到期、论点失效都会取代它 |
| 不执行 | 复盘里算「卖出指令后晚卖」 | 不算偏差 |
| 离场原因 | 持有到期 / 论点失效 | 换仓（取最后一次卖出时的原因；半仓换后剩余部分后来止损的记止损） |

指令里的卖出成交累计达到数量后指令消失；没卖完的卖出之后，剩余持仓的止损价不变，「今日操作」提示「止损单数量需改为 N 股」，直到再次确认挂单。

## 在系统里哪里看到

- 简报与页面「今日操作」里的「下次开盘卖出 N 股（换仓至 B）」，「记成交」预填卖出股数，旁边有「撤回」；名单里 B 那一行写换仓结论或不比较的原因。
- 计划卡片：A 显示换仓指令，B 显示「资金来自换仓 A」。
- 页面「复盘」的「换仓」块：每次比较一行（含继续持有）、执行情况、结论之后第 5 / 10 / 20 个交易日 A 与 B 各自的涨跌幅与差，汇总里的手续费估计合计与 B 跑赢 A 的占比。
- 对话里 `get_rotation_table` 读比较表，`save_rotation` 给结论，`withdraw_rotation` 撤回指令。

## 注意

- 仓位高于上限本身不产生任何卖出指令；没有候选的一天不比较。
- 对话里用户发起的比较不受「每天一次」与冷却限制，但复述里必须说出最近换仓次数，结论同样计入冷却。
- 先卖 A、再按计划买 B：B 可能没买到，那时 A 已卖出，钱留作现金，系统如实记录，不补救。
- agent 的判断和选股规则一样**未经验证**；每次结论都留记录并事后对照，样本数低于 `v3.retro_min_sample` 只给次数。这不是投资建议。
