# v3.1.0：每日简报、计划线、止损纪律、账户、页面与对话 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 v3.1.0：一条跨天的计划线（一只股票一份有效计划、每次变化记一行）、宿主算出的止损纪律与卖出指令、按成交与出入金算出的账户、定时产出并推送的每日简报、一个四块内容的页面和页面上的对话。

**Architecture:** 新增两层：**纯函数层**在 `execution/`（计划线的状态与止损算术、账户账本）和 `facts/`（名单连续性、简报正文）；**编排层**分三个包——`facts/review.py` 等做宿主的每日复查与待办（不调模型），新包 `runtime/` 封装 Pi 进程与假实现、单进程互斥、对话轮次，新包 `daily/` 做定时任务（采集 → 事实 → 复查 → 草稿 → 简报会话 → 最终简报 → Discord）。工具面在现有 `toolsurface/` 上扩到 31 个工具；页面接口在 `api/` 下按 `APIRouter` 加入现有外壳，写接口直接调用工具面的宿主函数（同一套校验，不另写）。前端只改 `web/src/routes/Home.svelte` 与新目录 `web/src/lib/home/`。数据改动在迁移 034：改造 `v3_plans` 为计划线，新增变化记录、持仓复查、出入金、作废、简报、对话、设置八张表。

**Tech Stack:** Python 3.11 / FastAPI / psycopg / PostgreSQL；Svelte 5 + bits-ui + Tailwind 4（`web/src/lib/ui` 现有组件层）；Pi 1.5.0（`--mode json` 子进程）；pytest（离线 + 一次性库 55433）、vitest。不新增 Python 依赖；前端不新增依赖（Markdown 自己解析，见 Task 6）。

**Spec:** `docs/specs/2026-11-06-v3.1-plan-line-account-and-web-design.md`（下文「spec §x」）。它依赖 `docs/specs/2026-11-05-agent-first-rebuild-design.md`（下文「v3 设计 §x」）§7、§15.3、§15.4 的运行时与会话规定。Pi 的命令行与事件名以 `docs/operations/pi-unattended.md` 为准。

- **不改旧口径**：`screen-1`、规则 v1、`rule_levels`（0.5 / 2 / 4 倍 ATR）、`size`、`WorkbenchConfig` 不动。
- **前端守护**（`tests/test_frontend_design_guards.py`、`docs/design-system.md`）：不用原色类名、十六进制色、emoji、`<style>`、裸 `<button>`、`{@html}`、原生 `confirm/alert/prompt`。新组件进 `design-system.md` §6。
- **spec 的固定取值（逐字）**：
  - 计划状态七个：`pending`（待入场）/ `open`（已买入）/ `closed`（已平仓）/ `expired`（已过期）/ `invalidated`（已作废）/ `replaced`（被替换）/ `cancelled`（已取消）；「有效计划」= `pending` 或 `open`。
  - 计划种类两个：`planned` / `adopted`（补录）。补录计划的 `thesis` 固定为「补录持仓，没有入场论点」。
  - 持仓复查结论三个：`holds`（成立）/ `broken`（不成立）/ `unknown`（无法判断）。
  - 出入金四种：`opening`（期初）/ `deposit`（入金）/ `withdrawal`（出金）/ `adjustment`（调整）。
  - 离场原因五个：`initial_stop` / `trailing_stop` / `max_hold` / `thesis_broken` / `manual`。
  - 配置默认：`pending_cap = 3`、`valid_sessions = 5`、`max_hold_default = 20`、`trail_atr = 3`、`brief_budget_minutes = 20`、`chat_turn_seconds = 300`；`top_n = 5` 不变；`MAX_HOLD_RANGE = (3, 30)` 不变。
  - 面向用户的固定文案：「止损已触及，未见卖出记录」「下次开盘卖出」「缺日线，无法检查止损」「缺日线，未复查」「缺日线，未能给出止损」「未确认止损单」「止损单需上调至 {Y}（当前挂单 {X}）」「继续持有」「今天无法检查止损」「正在生成简报，请稍后再问」「未选定模型，二次确认未做」「二次确认未完成」「没有变化」「首次运行」「补录，不计」「现金为负，可能漏记入金」「未提供账户资金，未算股数」「最新收盘高于入场区间」「已持有」；页脚含「规则未经验证，不构成投资建议」；任何面向用户的文本不出现「降级」。
- **时间口径**：交易日用纽约日历（`data/calendar`）；成交时间带时区存 `TIMESTAMPTZ`，成交所属交易日按 `execution/positions._session`（纽约日期）；简报页脚用北京时间。

## Review Focus

1. 持仓股票当天没有日线（数据源缺漏）：该持仓当天不做止损判断，「今日操作」与简报写「缺日线，无法检查止损」，其他持仓照常 → Task 3 `tests/test_v3_review.py::test_missing_bar_marks_holding_unchecked`。
2. 补录持仓的成本高于现价且已触及目标：移动止损不能高于最新收盘 → Task 2 `tests/test_plan_line.py::test_trailing_stop_ignores_cost_floor_above_price`。
3. 作废一笔买入成交后，后面的卖出变成超卖：作废被拒绝（`position_invalid`），不写作废行 → Task 3 `tests/test_v3_tools_chat.py::test_void_buy_that_breaks_fifo_is_rejected`。
4. 简报会话的 Pi 进程无输出被超时杀掉、或最后一条助手消息 `stopReason == "error"`：简报行状态与未完成原因写明，草稿与宿主算的持仓操作不受影响，不抛异常 → Task 4 `tests/test_daily_session.py::test_killed_session_keeps_draft_and_records_reason`。
5. 页面对话一轮超时或被取消：事件流以 `error`/`cancelled` 事件结束，消息行状态如实，下一轮照常可问 → Task 5 `tests/test_api_chat.py::test_cancel_ends_stream_and_next_turn_works`。
6. 两条路径同时给同一只股票建有效计划（对话与简报会话各一次）：第二条被数据库的部分唯一索引拒绝，宿主返回 `active_plan_exists` → Task 1 `tests/test_migration_034.py::test_one_active_plan_per_ticker_is_a_db_constraint`。
