# v3.3.0：账户维度——仓位上限与换仓比较 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 v3.3.0：总仓位上限 60%；候选 B 按上限买不下时，agent 在可比的持仓里最多挑一只 A，给出「继续持有 / 半仓换 / 全仓换」；宿主把结论变成带数量的卖出指令与 B 的计划；每次比较留记录并在复盘里对照。

**Architecture:** 沿用 v3.1 / v3.2 的分层。**纯函数**新增 `execution/rotation.py`（仓位占比、「钱不够」判定、可比条件、卖出股数、冷却、手续费估计、事后对照与汇总），`plan_line` 增加换仓指令的优先级与取代、`plan_levels.size` 多返回一个不受总仓位限制的股数。**编排层**新增 `facts/rotation.py`（闸门、可比持仓、比较表、撤回）与 `facts/rotation_repo.py`（换仓记录的 SQL）；`agenda` / `view` / `review` / `retrospect` 接入。**工具面**新增 `toolsurface/rotation.py` 三个工具（35 → 38），`save_plan`、`continue_plan`、`revise_plan`、`save_holding_review`、`confirm_stop_order`、`record_trade` 按 spec 改。半仓或全仓的结论、B 的计划、A 的指令在同一次调用、同一个事务里落库。数据改动在迁移 037。前端在今日操作、计划卡片、账户概览、复盘、工具面板五处接入。

**Tech Stack:** Python 3.11 / FastAPI / psycopg / PostgreSQL；Svelte 5 + bits-ui + Tailwind 4（`web/src/lib/ui` 现有组件层）；pytest（离线 + 一次性库 55433）、vitest。不新增依赖。

**Spec:** `docs/specs/2026-11-11-v3.3-account-cap-and-rotation-design.md`（下文「spec §x」，含 §17 末尾的两处澄清）。它在 `docs/specs/2026-11-06-v3.1-plan-line-account-and-web-design.md`（「v3.1 §x」）与 `docs/specs/2026-11-08-v3.2-retrospect-research-and-page-polish-design.md`（「v3.2 §x」）之上；冲突以 spec 为准（spec §16）。

  - 「钱不够」：`max(额度内的股数, 0) < rotation_min_fill × 不受总仓位限制的股数`，且后者大于 0。判定用宿主规则价位。

- **时间口径**：交易日用纽约日历（`data/calendar`）；显示用北京时间（沿用）。

## Review Focus

1. 某只持仓当天缺最新收盘：它的市值算不进仓位占比，占比偏低、剩余额度偏高。三件事都要有：账户行标明「有持仓缺日线，占比偏低」；候选「钱不够」时当天不做换仓比较（闸门原因 `incomplete`，表里的数不可靠）；候选「钱够」时计划照常保存，但 `warnings` 里加一条「有持仓缺日线，仓位占比偏低」→ Task 2 `tests/test_rotation.py::test_exposure_marks_incomplete_when_a_close_is_missing`、Task 3 `tests/test_v3_rotation.py::test_missing_close_blocks_comparison_and_warns`、`tests/test_v3_tools_plan.py::test_save_plan_warns_when_exposure_is_incomplete`。
2. 总资产为 0 或负（现金为负且没有持仓、或只有对账记录为 0）：占比与额度为空，不除零，不比较 → Task 2 `tests/test_rotation.py::test_exposure_without_positive_equity`。
3. 持仓是小数股或奇数股（1.5 股、3.5 股、301 股）：半仓分别为拒绝、1 股、150 股 → Task 2 `tests/test_rotation.py::test_sell_quantity_floor_and_minimum`。
4. 对话里同一个 `request_id` 重发保存换仓结论：返回原来那一行，不产生第二行记录、不重复下指令、不新建第二份 B 的计划 → Task 3 `tests/test_v3_tools_rotation.py::test_chat_replay_returns_same_rotation`。
5. A 有换仓指令期间发生拆股：指令的股数按拆股比例调整，时间线有记录 → Task 2 `tests/test_plan_line.py::test_split_adjust_scales_rotation_sell_quantity`。
6. 用户在半仓指令之后一次把 A 全卖了：指令消失，计划平仓，离场原因「换仓」，不留下负的待卖股数 → Task 3 `tests/test_v3_tools_chat.py::test_selling_more_than_instructed_closes_as_rotation`。
