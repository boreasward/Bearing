# 提前移除 v2 实施 plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 v2 的代码、前端、测试、概念卡和文档从仓库里移除，只留 v3 用到的代码与外壳；删旧表的迁移写好并在一次性库上验证。

**Architecture:** 以 v3 两个入口的 import 闭包为准整块删除（后端与前端并行），再裁剪保留模块里没人调用的部分、归档概念卡、写迁移 033（两者并行），最后重写文档并跑三套全量。

**Tech Stack:** Python 3.11 / FastAPI / psycopg 3 / pytest；Svelte 5 / Vite / vitest；Postgres 17。

**Spec:** [docs/specs/2026-11-06-v2-removal-design.md](../specs/2026-11-06-v2-removal-design.md)（删什么留什么的上位依据：[v3 设计](../specs/2026-11-05-agent-first-rebuild-design.md) §9、§15.5）

## Global Constraints

- 直接在 `main` 的工作区里改；**子代理不执行任何会改 git 状态的命令**（`git add / rm / commit / stash / checkout / restore / reset / mv`），删文件用普通的 `rm`，移动用 `mv`；只读的 `git show / log / grep / diff / status` 可以用。提交由编排者在每个 Task 审查通过后按路径做。
- 并行的 Task 共用一个工作区：只改本 Task「Files」里列出的路径；别的 Task 的文件导致的失败只上报，不去修。
- **不连真实库**：不读 `.env` 里的数据库地址去执行任何语句，不运行 `python -m investment_assistant.migrate`、`facts run`。数据库测试只用 `INVESTMENT_ASSISTANT_TEST_DATABASE_URL=postgresql://test@127.0.0.1:55433/workbench_test`（一次性库，编排者已启动）。
- 不做 v3 第 2、3、4 步的任何功能；不重组保留模块的目录，不改名，不改保留函数的签名与行为。
- 不留兼容空壳：没有重新导出、没有注释掉的代码、没有「已移除」之类的占位注释。
- 冻结的 spec / plan（`docs/specs/`、`docs/plans/`、`docs/archive/`）只修失效链接，不改正文。
- **测试分级**：每个 Task 只跑与本 Task 相关的测试文件；离线全量 pytest、一次性库全量 pytest、前端 `npm test && npm run build` 三套只在 Task 5 跑一次。
- **审查一轮**：每个 Task 派一轮审查（`opus`），修复后由编排者看 diff 与相关测试确认，不派复审；全量 code review 只在 Task 5 做一次。实现子代理用 `sonnet`。
- Python 命令一律用 `.venv/bin/python`；离线测试用 `env -u INVESTMENT_ASSISTANT_TEST_DATABASE_URL .venv/bin/python -m pytest -q <文件>`。
- 删除前的基线提交是 `d082400`；要看被删代码用 `git show d082400:<path>`。

## Review Focus

1. **函数体内的 import 与字符串形式的模块路径**指向已删模块（`monkeypatch.setattr('investment_assistant.x.y', …)`、`python -m …`）：导入时不报错，运行到才炸。→ Task 1 的 `tests/test_no_dangling_imports.py`。
2. **保留代码的 SQL 字符串引用被迁移 033 删掉的表**：静态搜不到 import，运行到才报 `relation does not exist`。→ Task 3 的静态测试，加上夹具应用到 033。
3. **空库从 001 顺序建到 033**：033 的外键处理顺序只在已有全部表的库上试过，空库或缺 LangGraph 检查点表的库上可能失败。→ Task 3 的 `test_migration_033.py`。
4. **用户本机 `config/local.json` 里还留着已删配置类的键**（`workbench`、`notify` 等）：`load_config` 应当忽略而不是报错。→ Task 3 的配置测试。
5. **保留的概念卡引用已归档的卡**：`toolsurface` 启动时加载目录，一条悬空的 `related` 就会让工具面起不来。→ Task 4 的目录测试。


- 共享接口：`tests/conftest.py` 的夹具名（`workbench_db`、`v3_db`、`v3_tx`、`client`）在 Task 1 之后不改名；Task 3 只改它们应用的迁移清单。
